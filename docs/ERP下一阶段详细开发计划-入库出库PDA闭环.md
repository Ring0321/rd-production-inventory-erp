## 1. 当前阶段目标

下一阶段不扩展通用 ERP，不恢复旧平台模块，只围绕现场最关键的三条业务闭环开发：

1. 质检通过后，仓管员安排库位，叉车司机按任务扫码上架，系统形成可查的入库和库位台账。
2. 商务/销售提货单下发后，库管按库存和库位生成装车任务，叉车司机按库位和货物资料扫码装车，系统形成出库流水。
3. 二维码追溯页面能把一包货从生产、质检、入库、库位、出库、装车到订单客户串起来。

核心原则：

- 不让叉车司机承担库位管理职责；库位调整和确认始终由仓管员负责。
- PDA 页面按岗位动作设计，不做后台页面缩小版。
- 扫码录入优先，减少手工输入。
- 每一个库存变化必须有流水、有操作人、有时间、有来源单据。
- 每一个现场异常必须能反馈、能处理、能复核、能验收。

## B1. [ ] 梳理并固化入库上架状态机

**说明：** 明确质检通过后的入库上架流程，防止代码里出现“司机自己改库位”“扫码直接入库但仓管员不知道”等现场不适用逻辑。

**目标流程：**

1. 生产完成，形成货物包/批次。
2. 质检抽检并放行。
3. 系统形成待上架货物池。
4. 仓管员查看库位地图和空位。
5. 仓管员创建上架任务并选择计划库位。
6. 任务同步到叉车司机 PDA。
7. 叉车司机按任务扫码确认搬运到指定位置。
8. 如果现场放不下或货位不符，司机提交异常，不直接改最终库位。
9. 仓管员处理异常并确认最终库位。
10. 系统更新库存台账、库位占用和库存流水。

**验收标准：**

- [ ] 状态包含：待上架、已派单、搬运中、待仓管确认、已上架、异常待处理、已取消。
- [ ] 司机端不能直接完成最终库位变更，只能扫码确认或提交异常。
- [ ] 仓管员端可以确认最终库位并完成上架。

**验证方式：**

- [ ] 形成状态机文档。
- [ ] 状态机与权限角色逐项对应。

**依赖：** A1。  
**预计范围：** 小。

## 5. 主要风险和处理

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 前端源码基线缺失 | 无法持续开发，只能跑发布包 | 第一项先恢复源码基线 |
| 司机承担库位调整 | 现场责任混乱，库存不可信 | 司机只反馈异常，最终库位由仓管确认 |
| 二维码只做查看 | 无法支撑现场录入 | 做统一扫码入口，按角色和状态决定动作 |
| 库位变化频繁 | 台账滞后 | 上架、出库、异常处理都更新库位流水 |
| 重复扫码或多人并发 | 库存重复入库/重复出库 | 数据库事务、唯一约束、行锁和并发测试 |
| 现场网络不稳定 | PDA 操作中断 | 明确超时提示，关键动作可重试且幂等 |
| 只做本地测试 | 误判为现场验收 | 必须有现场试跑证据和整改复测记录 |
