# AI 国内接口与扫码问货实施规格

## 用户决定与本轮范围

2026-10-12，用户选择国内模型API，保留现有ERP架构。已提交起点为 `ab437483686e40efc827aeb0655cf0aa4ab42bc7`，本轮开始时工作树干净。继续采用Spring Boot/Security/MyBatis、MySQL、Redis和Vue/Element Plus，不恢复已删通用AI平台模块、不新建第二套库存数据。

先完成“扫码后查真实事实、选择问法、获得受约束的AI解释”这一条只读路径。企业真实包号、客户、型号、炉号、位置、单据、人员及附件留在ERP。第一版以预定义状态/进度/下一步问法开始，不开放任意SQL、任意工具调用或自动业务操作；自由提问解析、单据识别、配吨优化列为后续，不能将本轮受控问法冒充已完成的任意问答。

用户已确认供应商为GLM，允许发送“流程状态＋汇总包数/重量”，密钥已准备，后续在本机配置；具体模型和费用上限尚未确认。默认真实调用关闭。只传受控枚举和源记录汇总，不传客户、包码、型号、炉号、库位、单据、人员、自由备注、历史原文或附件。汇总不等于匿名，小批次仍有推断风险；第一版不外发单包重量。附件识别需要另行确认图片/文本外发边界，本轮不上传原附件。

## 设计边界

- 后端所有新业务在 `rd-erp-inventory/com.ruiding.erp` 的AI辅助功能内，启动/配置仍归 `rd-erp-server`。复用既有包件查询/工作上下文及权限，不让模型直接连接数据库。
- 前端从内部二维码包件页面接入，显示来源与查询时间；Web/PDA均保持原表单和库存动作。匿名用户看原公开追溯，不获得模型调用入口；读不到不等于不存在，不以0填未知数据。
- 静态权限复核：生产、质检、仓管和只读岗位的种子授权包含包件查询；商务、司机默认没有。第一版仅开放已有 `rd:package-unit:query` 的账号，不增加新岗位授权，不给司机增加扫码任务。每次读取及缓存核对都重验实际权限、登录人和必需租户，不依据角色名猜测。
- 先核对实际包件/来源/权限，再构造显式白名单的模型上下文。原问句、客户/包码/库位/单据/人员/备注/附件不直接透传，数据库文本及附件不能作为模型指令。
- 流程状态采用服务端枚举，不外发自由备注。模型返回结构化解释要点，必须是当前事实与岗位允许的范围；真实数值和操作链接由ERP返回/渲染，不由模型编造或修改。模型不能把待核解释成失败，不能代替质检放行或仓管最终过账。
- 接口采用供应商公开支持的聊天兼容协议，不增加Spring AI大框架或升级原内核。密钥仅来自环境/本机忽略配置，前端与仓库不可读密钥。供应商/模型未配置时明确“未配置”，不提供假AI回复。
- 可信服务器配置限定官方HTTPS端点；客户端不能指定URL、模型、系统提示或工具。拒绝非允许域名、海外区域、重定向和无效/超量响应；错误返回不得带请求头、密钥、原请求或原供应商响应。
- 无真实密钥/费用授权时只做本地模拟协议测试，并明确标为接口模拟；不对供应商发送企业数据，也不作实际模型验收完成声明。只记录真实接口提供的token用量，不虚构人民币费用或把缺失用量记成免费。
- 关键调用无自动付费重试；请求元数据（不含token、事实明细）按账号/租户/包件保存在本机同浏览器持久存储，用Web Locks协调标签页，关闭重开仍只核对原UUID；不支持Web Locks或不是安全上下文时禁止模型调用，ERP事实查询不受影响。相同请求的后端去重、并发、未知结果及身份/租户/离页/换包保护按实际接入契约验证。AI失败不改变任何库存、质检、任务和库位数据，原ERP继续可用。
- 采用Redis原子预留：公司级日调用次数、用户级分钟次数和24小时请求去重。次数不是人民币硬预算，实际费用须在平台侧设定并人工确认。超时/中断/不明返回保留原请求，不自动重发；核对原请求只读已存结果。Redis不可用时禁止真实调用。缓存只存受控要点、用量和事实指纹，不存密钥、客户明细或提示原文。
- 第一版模型仅从当前允许的解释要点中选择并排序；文案、实际数值和权限入口都由ERP生成。这是受控解读，不是自由聊天。源记录统计含作废包独立状态，登记总重不是实磅、计划量、余量或订单可发量；不从兄弟包推断本包质检结论。

## 官方接口依据

2026-10-12查验：[智谱对话补全官方文档](https://docs.bigmodel.cn/api-reference/模型-api/对话补全) 明确普通开放平台端点为 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，Bearer认证、非流式响应、`response_format.type=json_object`、`max_tokens`、`request_id` 和 `usage.total_tokens`。固定此端点，不开放客户端或环境URL覆盖，不接Coding Plan端点。具体可用模型须由账户确认，本轮没有默认指定昂贵或“最新”模型，没有固化搜索摘要费用。

初始合同：GET `/rd/ai/package/context?packageCode=...` 返回本地事实及配置门槛；POST `/rd/ai/package/ask` 只接受包码、受控问法和UUID请求键。两者都要求包件查询权限，不记录请求/响应正文到访问日志。模型输入只含受控流程状态、同源汇总、受控问法和允许解释键，不含请求包码/UUID/用户/租户ID。GLM收到的是新随机请求ID，不是ERP身份。

GET `/rd/ai/package/result` 仅以原包码、原问法和原UUID读回执，不预留调用、不访问模型。开关关闭仍可核对成功回执；回执过期/缺失返回RECEIPT_MISSING并保留待核，不视为未执行或免费。后端回执查询为原子读取，完成写回需匹配原预留nonce＋指纹，不能用旧响应覆盖删除后重建的请求。

## 本机配置与启用顺序

本地隔离启动读取被Git忽略的 `temp/local-runtime-patent/.env.local`，不把密钥写进application.yaml、前端或聊天。服务器部署使用受保护的进程环境变量。本轮未修改这个私密文件，也没有读取/配置GLM密钥。

| 环境变量 | 用途 | 默认 / 启用条件 |
| --- | --- | --- |
| RD_AI_ENABLED | 真实调用总开关 | false；本轮保持关闭 |
| RD_AI_GLM_API_KEY | 普通开放平台API密钥 | 空；仅在本机/服务器私密环境填写，不发聊天 |
| RD_AI_GLM_MODEL | 实际可用文本模型ID | 空；由账户负责人确认JSON输出、thinking参数及实际计费适用性，不默认最新模型 |
| RD_AI_COST_APPROVED | 费用与字段范围已核定的启用门槛 | false；模型/预算未确认时不得改true |
| RD_AI_DAILY_CALL_LIMIT | 公司/租户级每天新调用预留上限 | 0；合法范围1-1000，具体值由负责人确认 |
| RD_AI_USER_MINUTE_LIMIT | 每人每分钟新调用预留上限 | 2；合法范围1-10 |
| RD_AI_MAX_OUTPUT_TOKENS | 单次输出token上限 | 512；合法范围128-1024，实际兼容性仍需A5验证 |

顺序：先确认模型与平台预算/数据条款 → 本机私密配置 → 重启本项目已验证归属的后端进程 → 在已授权内部包件页查看READY → 明确发起少量请求 → 对照ERP事实、实际token和平台账单验收。调用次数上限包含预留和失败请求，不是人民币预算；不知道用量不能记为免费。原请求超过24小时回执缺失时仍保持待核，不能当作未调用，需负责人在平台核对后处理。
