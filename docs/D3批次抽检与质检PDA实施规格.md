# D3 批次抽检与质检 PDA 实施规格

## 当前工作与原目标

源基线 `936ef7203e127162f4e034896f7871ab1b766931`，支持总计划 D3 与 E4/E5。原有质检仅关联一包；本轮要实现明确的检验覆盖成员、实际抽样成员、检测项目与双人复核，再在专用 PDA 和每包追溯中呈现。完整 E 的实体标签/公网/实机/岗位验收不缩小，也不据本轮本地证据提前关闭。

生产任务可能包含多个型号、炉层和产出，不能作为自动放行范围。本轮检验批次从一条真实生产产出记录的包件中明确选择，允许部分包，不要求将全部包或整个生产任务放行。没有生产来源的旧包仍可单包办理。客户/型号/炉号/炉层必须一致，源包状态必须适合质检。具体抽样数量与企业检验标准由质检人员确定，系统不虚构抽检比例。

## 生命周期和约束

- 扫代表码只定位生产来源和已有检验单，不改变任何包状态。默认只选可检的扫码包，用户明确勾选本次实际覆盖包，也可用“选择可检整批”跨页选择全部实际可检包后剔除；超过 200 包或分页失败/范围变化时保留原选择，不静默截断。扫码包已检时仍可选同来源的实际余包，不强制再次纳入已检包。检验单代表包取本次实际覆盖清单中的一包；抽样包是覆盖清单的非空子集。
- 每个检测项目绑定实际抽样包；每个被选抽样包必须有检测项目。服务端按实测值与上下限判定，不接受客户端伪造 qualified；上下限不能倒置，样包不能来自清单外。
- 草稿创建时锁定所选包并建立唯一活动质检占用，阻止同一包在多个草稿或旧单包单中重复办理。每包一码不变。旧单包历史不回填不存在的抽样事实。
- 提交只将实际覆盖包转为 QC_PENDING；复核通过只将这些包转为 QC_PASSED，未选包维持原状态；不通过转 QC_REJECTED，终态释放活动占用。包状态、检验单、成员和必要领域审计在同一事务完成，审计写入失败也全量回滚。系统异步日志仅辅助，不作为放行或追溯的权威；原请求重试不重复产生领域状态事件，也不重复计算产量或放行次数。
- 提交人与复核人必须不同，操作人来自登录身份，司机/销售/只读不能办理。通过必须有合格的实测项目；不通过原因必填。未通过包仍不能进入上架任务。
- 新批次创建有 clientRequestId，绑定原内容和录入人；丢响应重试原请求返回同一单。PDA 在发请求前保存原请求，待核期间不修改或释放编号；提交/复核同人同结果重试不改原时间，内容或身份不一致拒绝。
- 锁顺序遵从现有生产与包件约束；成员按 ID 排序锁定。并发重叠清单不能产生两份活动占用，最终过账不归质检或司机执行。
- 每包追溯从真实检验成员关系查询；内部显示覆盖数/抽样数/本包是否抽样及单据入口，公开仅现有脱敏结论/时间线，不展示其他包、客户、人员或库位。

## 前后端合同

继续使用既有 `rd:quality-inspection:query/create/submit/approve`，不增加业务授权。

1. `GET /rd/quality-inspection/scope?packageCode=&pageNo=&pageSize=`：响应 `{representative, productionOutputId?, packages:{list,total}}`。list 行为包件真实字段加 `eligible:boolean, activeInspectionId?, activeInspectionNo?`。按生产产出分页；旧无源包只返回自己。包码支持现有稳定链接提取，不导航到输入域名。
2. `POST /rd/quality-inspection/create-batch`：`{packageId, packageIds, samplePackageIds, items:[{samplePackageId,itemCode,itemName,standardMin?,standardMax?,measuredValue,unit?,remark?}], remark?,clientRequestId}`，返回 Long 检验单 ID。最多 200 包，重复/清单外/混源/活动占用拒绝。
3. 既有 get 响应扩展 `productionOutputId?, clientRequestId?, registrarId?,registrarName?,members:[{packageId,packageCode,packageWeight,sampled}],coverageCount,sampleCount,events`。events 来自同事务领域表，含真实 action/actor/beforeStatus/afterStatus/time/range/request，不伪造旧历史。旧单无成员记录时范围为既有代表包；不编造其历史抽样标志。items 增加可空 `samplePackageId`。
4. 既有 page 支持服务端 `status,inspectionNo` 筛选和真实分页总数。submit/approve/reject 地址保留。
5. 内部包追溯可空新增 `qualityCoverageCount,qualitySampleCount,qualitySampled`；仅有实际成员关系时填写，公开省略。qualityInspectionId 来自实际成员范围。
