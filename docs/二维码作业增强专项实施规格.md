# 二维码作业增强专项实施规格

日期：2026-10-15。基线：11c7809899301012264df5b6d0d2f156a42eb413。用户本轮确认加入截图中的三项：可视化连续扫码、货物追溯关系图、弱网待同步箱。标签拍照 OCR、签名护照、整套 OpenEPCIS 不属于本轮授权范围。

## 1. 业务与技术边界

沿用垛序 ERP 1.0.0 + Git、Vue 3、Element Plus、Spring Boot、MySQL 和现有角色体系。原一包一码、稳定数字链接、批次代表扫码、质检覆盖/样包精确归属、原请求核定和 3D 示意库位保留。仓管扫描、选择/更新库位和最终过账；司机仅接收任务、搬运和反馈异常。本专项不完成 C5-R2/R3，不扩大 GLM 外发范围、不调用模型、不改历史二维码、不建立第二库存账。

所有相机解码、WASM、关系图和浏览器存储均使用本机/自有服务器资源，不依赖外部 CDN、云数据库或公共解析服务。首次加载和厂区移动相机仍需要可达且可信的部署入口；缓存草稿不等于完整离线 PWA。不得宣称实体袋数自动识别、自动定位、签名、防伪或现场验收通过。

## 2. 用户路径

1. 仓管在原入库或装车任务里打开连续扫码工作区；任务成员、版本和可选状态来自原 ERP 查询。
2. 启动相机或选择本机标签图片；仅解析可见码。图中标出识别位置，记录本任务候选、重复、非本任务和状态不可用，不把识别事件直接写为出入库。
3. 当前任务下的候选持久化到本机待同步箱，按登录用户、租户、业务类型和任务隔离。仅保存包号、原任务版本和本机状态/时刻，不保存令牌、客户、人员、附件原件或自由文本二维码。
4. 仓管明确点击重新核对，服务器重读同一任务。只有版本、身份、成员和状态均有效的候选能转为所选清单；版本变化、非成员、已处理、任务停用进入冲突，断网/查询失败保持待核。
5. 待核记录只表示已采集；已核对表示当前服务器认可其可选性；最终核验与库存过账继续调用原流程，并保留原请求幂等/待核保护。禁止后台自动发送库存写请求。
6. 内部包件追溯页新增关系图。节点来自生产来源、实际质检覆盖/样包、库存流水、任务成员及历史快照；点击节点查看资料，登记库位可跳转原 3D 空间定位。真实任务/单据连接可按原权限打开。
7. 图中未加载、受限或截断内容明确标记，不把同炉号、同型号或计划位置当成实际覆盖/搬运/出库事实。公开页面不请求内部图 API。

## 3. 数据与生命周期

扫码候选须通过现有包码/数字链接结构核对，保留精确大小写身份；拒绝恶意 URL、非包链接、重复任务成员和未知重量补零。统计使用候选对应的当前登记重量，不把一包恒定视为一吨。识别边框不代表已提交；同码去重仍需本机候选去重和服务器原幂等机制。

Dexie 仅作 IndexedDB 适配。恢复网络不自动入库/出库，不自动覆盖冲突。列表须有本机待核、服务器核对、冲突/已处理状态及逐条清除动作。页面关闭/缓存停用时停止相机；切换任务、版本、登录身份、租户或权限时使晚到响应失效。原未决写请求存在时禁止把新的候选清单传入原流程。配额/存储不可用时显式报错，不显示保存成功。

关系图接口为只读、登录且包码查询权限受控，沿用租户隔离；不修改数据库。质检关联只能取实际覆盖成员，样包单独标识。被替换或取消的装车成员保留历史，不继承其他包的出库；库存移动连接来自该包真实流水。使用服务器输出的稳定节点 ID，不在前端猜来源 ID 或构造自由跳转地址。

## 5. 验收条件

- 连续画面/本机多码图片识别可见真实 QR；同任务、重复、错包及不可用状态正确，实际登记重量合计正确；零外站请求；相机资源释放。模拟帧不冒充实体相机实扫。
- 本机采集不发库存写请求。退出/换租户不能读他人箱；重新进入恢复原任务候选；断网保留待核，旧版本与已处理包不能传回清单；正常核对后必须仍由人点击原核验/过账。
- 图与真实包件/来源/实际质检成员/任务历史/库存流水一致。点击及原 3D 联动可用，未知/无权限/大范围限制不被隐藏；匿名和司机不能借新接口查到内部关系。
- 1440/390/320 px 无文字溢出，真实图像非空，错误/空数据与生命周期表现明确；原批次代表扫码、原请求核定、仓管确认和司机免扫码通过回归。
- 通过本地测试后仅勾选本专项本地项；公网 HTTPS、厂区网络、标签耗材、PDA 实机、真实人员签字及 C5 后续仍未完成。
