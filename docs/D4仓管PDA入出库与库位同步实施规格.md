# D4 仓管 PDA 入出库与库位同步实施规格

## 目标与当前基线

源基线 `efb8d75503517db2dcd67bc48441d25d2206df20`。总计划 D4 依赖已有 B5/C5 的仓管业务接口，并补齐 E4 同码岗位入口和 E5 真实逐包流转。上一轮 D3 已完成本地技术验收；完整 E、实体标签、公网和现场岗位签字仍未完成。本轮继续开发，不改变最终目标。

用户已确认尚无打印机/PDA/扫码设备，先使用本地二维码内容及浏览器。实体连续实扫不少于 20 包仍保留在 D4/D6/F 现场验收，不能以码串输入测试替代。正式二维码身份和每包净重、包号均保持不变。

现有前端仓管岗位入口仍指向 Web 工作台。已有 `RdPutawayTaskApi` 和 `RdLoadingApi` 支持定位、核验、最终确认及异常办理，沿用这些合同和服务器权限，不重建第二套库存逻辑、不由浏览器直接访问数据库。

## 用户路径及保留规则

1. 仓管从 `/pda` 进入独立 `/pda/warehouse`，显示库位、上架、装车三个工作视图，不带 Web 后台侧栏或标签菜单。
2. 库位视图从服务器读取实际占用、预占、容量和状态，按仓库/库区/库位文字筛选。空位不只按库存为零判断；冻结、停用、预占和容量未知必须明确展示，不编造可放数量。
3. 上架视图查看任务或输入一包码，读取该任务的真实包件、客户/型号/炉号/炉层、计划库位及司机。定位不写库存、不自动核验整批；仓管明确勾选本次实际到位包件，再批量核验。剩余包和已核验包分别保留，重复/错包由服务器拦截。
4. 全部任务包件核验到位后，仓管选择/确认实际库位，明确执行最终入库。位置更新和库存过账仍在后端同一业务事务完成；司机不扫码、不更新位置、不最终过账。
5. 上架异常由仓管查看并填写处理说明，选择可用库位后改派；司机资料使用原任务/服务器选项，不能凭空生成司机身份。容量不足、冻结、版本变化仍由服务器最终拒绝。
6. 装车视图按任务查看提货单、客户、车牌、各包计划取货库位、型号/炉号/炉层、包数和重量进度。保持一个装车任务派给司机，不自动拆成“装车小组”。
7. 输入任务中任意包码后定位已锁定实际包件，仓管勾选本次实际装车包件并核验；未装包不自动出库。全部所需包件核验完毕后，仓管明确最终出库，扣减库存、记录流水并释放对应库位占用。
8. 装车异常支持原有“退回司机继续执行”“替换包后继续”“取消任务”三种办理；替换包必须经原服务器的客户、型号、炉号、炉层、在库和占用检查。不把异常处理等同于最终出库。
9. 本地码串提取沿用 `rdDigitalLink`，不访问输入链接域名、不自动改写纸码。PDA 模式从数字身份页带入实际 taskId/packageCode；无操作权限只读，司机不得因访问此 URL 得到仓管能力。

## 请求、安全与同步

- 所有界面权限使用既有 `rd:putaway-task:query/confirm/assign` 和 `rd:loading-task:query/dispatch`；服务端权限是最终边界。查询能力不能推导出办理能力。
- 批量核验使用原后端幂等键及实际清单。发送前持久保存原请求，绑定页面进入时的用户和有效租户；超时/丢响应只重试原请求，不新编号或更改成员。换号、换租户或卸载后不启动后续写请求，原账号可以恢复。
- 明确业务拒绝和结果未知分别处理；结果未知时锁住相关表单，不用“取消请求”掩盖可能已写入的业务。最终确认和异常处理须重新读取实际状态/版本，防止以过期详情覆盖其他仓管的处理。
- 每次成功办理后刷新实际任务和库位数据，向其他 Web/PDA 页面展示同一后端结果；不通过 UI 乐观加减来声称库存已同步。Web 页面重新查询与 PDA/数据库的占用、数量、重量、包状态必须一致。
- 可见且有查询权的 Web 库位地图、Web 库存台账及 PDA 库位视图每 5 秒只读刷新，重新切到可见页面时立即核对；隐藏、停用、卸载或换身份/租户时不继续更新。已在读取时不重叠请求，旧响应不能覆盖最新手动查询；后台刷新不更改仓管已选成员、库位、异常说明或待核请求。台账尚未提交的筛选输入不自动查询。验证时必须在另一端已打开的页面观察实际更新，不能仅靠手动刷新证明自动同步。
- 查询失败保留显式错误和重试入口，不展示伪造的空库位。任务分页完整呈现总数，扫码定位不局限于前 20 条任务。

## 接口与数据归属

| 模块 | 沿用合同 | 归属与限制 |
| --- | --- | --- |
| 库位 | `GET /rd/putaway-task/location-map` | 后端计算实际占用/预占；只读，不改位置 |
| 上架任务 | `/rd/putaway-task/page`、`get`、`batch-scan/preview`、`batch-scan/confirm`、`confirm`、`reassign` | 服务端校验任务、版本、成员和容量；核验与最终入库是不同动作 |
| 装车任务 | `/rd/loading-task/page`、`get`、`batch-scan/preview`、`batch-scan/confirm`、`confirm-outbound`、`exception/resolve` | 服务端校验锁定包、计划和业务状态；只实际成员最终出库 |
| PDA 前端 | `frontend/src/views/rd/pda/warehouse/` | 页面组合、现场选择、待核请求、加载/错误/重试；不复制库存业务规则 |
| 岗位与追溯 | 现有 workspace profile、route、数字身份动作 | PDA 模式优先新仓管入口，Web 模式保持原管理页 |
| 验证 | `scripts/verification/`、前端就近测试 | 真实本地 API、实际浏览器、跨页面状态；所有测试资料标记非现场 |

表格正式导出仍采用黑色三线表，无底色。沿用现有 Spring Boot/Vue 3/Element Plus/MySQL 架构，无新增服务或外部标签平台；开发版本以本项目既有 Git 提交和台账记录，不另引入第二个版本体系。
