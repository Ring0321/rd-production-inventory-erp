## 数据与界面边界

- GET 本人上架/装车的列表和详情，是唯一司机任务来源，不以仓管查询列表加客户端筛选替代权限。
- 身份绑定进入页面时的账号和有效租户；每个接口入口及等待后核对最新身份/能力。失效页面不应用迟到结果、不开启下一读取/反馈。
- 任务详情只读目标位置和真实资料，包码只作为资料或来自已有深链高亮；不添加扫码框或位置更新输入。
- 分页只有成功后推进页码；详情请求按代次核对 id，导航取消旧详情应用；错误显示实际不可读取和重试入口，不能显示伪造的“没有任务”。
- 异常单必须从原任务关联实际成员，不能在表单打开后将它提交给后来切换的任务；返回和实际记录未确认不报成功。现有异常请求的未知结果恢复能力须先复核，不通过盲重试/客户端推断补造记录。
- 现场连续实扫20包、设备、网络和真实岗位签字属于仓管 D4/D6/F，司机免扫码不删除该门槛。本轮仍按用户要求做本地软件，不等待硬件采购。

### 后端只读支持交接

上述上下文已返回，主任务接收结论和源码位置并立即原生关闭；支持未执行测试/服务/数据库/网络，不把其源码判断作为运行证据。

- my-page、my-get、exception 分别需要各模块 execute 能力，按登录身份和当前任务归属检查，不需要额外 query/confirm/dispatch 权限。上架列表默认活动状态；装车只有 activeOnly=true 才筛活动状态。本任务两页面仅用本人接口，完成/取消任务可本人查详情但不能报异常。
- 上架反馈仅 ASSIGNED/MOVING，装车仅 ASSIGNED/LOADING。插入 OPEN 异常、增加任务版本并转 EXCEPTION_PENDING 同事务完成，返回真实异常 ID；不改目标库位、扫码进度或库存，重复反馈随后因状态拒绝。原键/请求级幂等不存在，不得自动 POST 重试。
- 请求关联包可选，为空是整任务异常。上架非空 selector 若 `/pkg/` 等规范化为空，当前实现会误转为整任务异常；R1/P2，源 `RdPutawayTaskServiceImpl` 613/1153，须拒绝并加无写入用例。
- 装车关联行虽然属任务，若 CANCELLED/OUTBOUNDED 仍会被当前 resolver 接受并冻结整任务，但历史追加会跳过该行；R2/P2，源 `RdLoadingDispatchServiceImpl` 904/795 及 `RdLoadingTaskLineMapper` 12，须拒绝并参数化验证。
- 已收到真实异常 ID时可按本人详情的该 ID/关联/内容核对，包括已处理记录。丢响应只能保守查看新增记录，不能靠状态/版本或同文本的新增记录证明是本请求（同账号同内容并发无法区分因果）；无匹配、多匹配、基线未知、失去归属或读取失败必须保持待核。角色、字段长度、类型枚举仍沿用现有 VO。
