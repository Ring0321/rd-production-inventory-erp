## R1 业务合同

1. 仓管从异常待处理的原装车任务提出少装申请，选择明确的未核验包件并填写真实原因。上限每次 100 包；必须至少保留一包。已核验、已出库、取消、非任务成员及重复 ID 均拒绝。全单取消仍走原异常取消流程，不借少装清零。
2. 后端保存完整有效计划快照、拟减少成员、各行重量/库位/货物信息、原任务版本与计划版本、原提货单版本、原数/减量/剩余数和净重。数量与重量由后端实际成员计算，不接收前端自报总数或客户变更。
3. 商务在原提货单详情中核定通过或退回，必须填写核定说明且不能核定自己提出的申请。核定使用独立权限，不授予司机或仓管；登录名/确认人由后端身份获取，不允许前端代填。
4. 核定时锁定任务及申请并检查旧版本和完整计划快照、有效提货单、选中包当前在库与占用关联。任务/提货单/成员发生变化时显示已失效且拒绝通过，须重读并重新提议，不沿用旧批准。
5. 创建采用任务内幂等键与请求指纹；同键同身份同内容重试返回原结果，同键不同内容拒绝。同一有效版本仅一份待核定/已通过申请。核定带申请版本；重复相同结论与说明可恢复已提交结果，不覆盖其他核定。
6. R1 仅写少装申请及核定记录，不修改提货数量、任务状态/成员、占用、PCS、库位、库存台账或出库流水。状态为待商务核定、商务退回、已核定待变更或已失效；“已核定”不等于任务减量，更不等于实际出库。
7. 仓管 Web/PDA 和商务提货单详情使用同一查询合同。切换任务/版本、页面失活或身份失效清除旧草稿；写入失联进入待核查询，不自动再发变更或宣布失败。叉车司机无申请/核定入口和权限。

## 数据与授权

在原 loading 业务内新增 `rd_loading_reduction` 记录表、同库可重复升级与空库初始化。查询限定一个明确 taskId 或 pickupSlipId、最多返回最近 100 条，不设跨公司开放接口。新建申请需 `rd:loading-task:dispatch`；核定需 `rd:pickup-slip:approve-reduction`；查询需原装车或提货查询权限。沿用租户隔离和现有角色菜单，岗位不是逐页自由授权。

实施补强：申请还需 `rd_warehouse` 或 `super_admin` 岗位，核定还需 `rd_sales` 或 `super_admin` 岗位；司机始终硬拒绝，原审计角色的历史派单权限不形成少装申请权。绑定每包版本、唯一占用记录 ID，并核验逐条提货明细的归属、型号、订单、炉号/炉层、包数及净重。包件离库、位置/版本/占用变化使历史核定显示已失效，不覆盖历史结论。净重存 `decimal(24,6)`，接口以十进制字符串返回核定汇总和包件快照，避免前端大数精度损失。

失联补强：`GET /rd/loading-task/reduction/get` 支持按申请 ID 或 taskId + 原幂等键精确只读查询，不受最近 100 条列表窗口限制。查不到或返回不匹配仍为待核，不能推断原写入失败并新建请求。列表、精确查询及写入均校验租户、权限和原身份。
