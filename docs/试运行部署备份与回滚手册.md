# 试运行部署、备份与回滚手册

## 1. 试运行目标

试运行环境用于真实业务上线前的连续运行和人员培训。建议服务器至少 4 核 CPU、8 GB 内存、200 GB SSD；数据库数据盘与系统盘分离，时区统一为 `Asia/Shanghai`。

| 组件 | 版本 | 对外端口 | 说明 |
| --- | --- | ---: | --- |
| Nginx + Vue 3 | Nginx 1.27 | 9000 | 唯一对外入口 |
| Spring Boot | Java 21 | 不暴露 | 由 Nginx 转发 `/admin-api` |
| MySQL | 8.4 | 不暴露 | `utf8mb4`，持久化命名卷 |
| Redis | 7 | 不暴露 | AOF 持久化并设置独立密码 |

## 2. 首次部署

1. 获取已验收的 Git 提交，安装 Docker Engine 24+ 与 Compose v2。
2. 将 `deploy/trial/.env.example` 复制为 `deploy/trial/.env`。
3. 设置互不相同的数据库密码和 Redis 密码，不使用示例值。
4. 执行下面命令：

```bash
docker compose --env-file deploy/trial/.env -f deploy/trial/compose.yaml build
docker compose --env-file deploy/trial/.env -f deploy/trial/compose.yaml up -d
docker compose --env-file deploy/trial/.env -f deploy/trial/compose.yaml ps
```

使用发布 ZIP 时无需源码编译，将上述文件名替换为 `deploy/trial/compose.runtime.yaml`。运行时 Compose 直接封装发布包中的 `backend/yudao-server.jar` 和 `frontend/` 静态文件。

空数据库会依次执行系统基线、RD 业务表、性能索引和岗位权限脚本。已有数据卷不会重复执行初始化脚本，升级时必须按版本说明单独执行幂等升级 SQL。

## 3. 上线检查

| 检查 | 合格标准 |
| --- | --- |
| 容器健康 | MySQL、Redis、backend、frontend 均为 healthy |
| 登录 | 管理员和五类业务角色均能登录 |
| 权限 | 允许接口成功，越权接口返回 403 |
| 库存 | 台账、可用量、锁定量、重量与当前 Excel 基线一致 |
| 订单 | 应入数量、实际产额、差额、调拨后差额正确 |
| 出库 | 确认后库存扣减且订单状态实时更新 |
| 审计 | 创建、确认、取消、调整和导入动作均可追溯 |
| 看板 | 指标、趋势、排行和待完成订单可正常加载 |

## 4. 备份策略

试运行阶段目标为 RPO 24 小时、RTO 2 小时。建议每日全量备份保留 14 天，每周备份保留 8 周，每月备份保留 12 个月，并复制一份到服务器外的受控存储。正式大规模运行后应增加 MySQL binlog 和增量备份，将 RPO 收紧到 15 分钟以内。

Windows 本地演练：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/backup/Backup-RdErp.ps1
powershell -ExecutionPolicy Bypass -File scripts/backup/Test-RdBackupRestore.ps1
```

每次备份包含 `.sql`、`.sha256` 和 `.json` 三个文件。备份成功不等于可恢复，至少每月执行一次隔离库恢复和关键表行数核对。

## 5. 升级流程

1. 公告维护窗口，停止导入、调拨确认和出库确认。
2. 记录当前 Git 提交、镜像 ID、数据库版本和业务总量。
3. 生成全量备份并执行隔离库恢复演练。
4. 先执行目标版本新增的幂等升级 SQL，再构建新镜像。
5. 执行 `docker compose up -d --build`，确认所有健康检查通过。
6. 回归登录、库存分页、订单分页、调拨、出库、日报、看板和审计。
7. 观察 30 分钟无持续错误后结束维护窗口。

## 6. 回滚流程

应用故障优先回滚代码：切回上一个已验收提交或镜像，重新启动 frontend 与 backend，不回退数据库。只有升级 SQL 造成结构或数据不兼容时才进行数据库恢复。

数据库恢复前必须停止 backend，再备份一次故障现场库。先将目标备份恢复到隔离库，核对 SHA-256、表数量和关键表行数；确认后才允许使用 `Restore-RdErp.ps1 -AllowPrimaryDatabase -ReplaceTarget` 覆盖主库。恢复后清理 Redis 缓存并重新执行权限回归。

禁止在日常维护中执行 `docker compose down -v`，因为该命令会删除 MySQL 和 Redis 数据卷。

## 7. 监控与容量

- 每日检查容器状态、磁盘空间、备份结果、失败登录和操作日志失败记录。
- 数据盘使用率达到 70% 时扩容，不等待磁盘写满。
- 慢查询超过 1 秒进入排查；看板聚合在百万级库存批次前增加指标快照或 Redis 短缓存。
- Excel 大文件保持预检后确认，禁止直接绕过任务导入数据库。
- 每月执行并发匹配、并发出库和重复确认回归。
