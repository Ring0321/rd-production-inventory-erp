# C5 装车批量换货实施规格

## 本轮目标

2026-10-12，按用户“先写大头的”调整执行顺序：先补 C5 装车主业务，D5 后续交互暂缓。以 `c8ee2b3` 为已提交基线，保留未提交的 D5 本人任务读取和测试，不覆盖原附件，不新建 ERP 服务或装车子任务。

仓管在同一张异常装车任务内登记多对原包和替换包，查看实际在库替换货的客户、型号、炉号、炉层、位置和净重，核定整份清单后一次处理。旧包释放装车占用但仍在原库位；新包建立占用、等待仓管实际核验；已核验且未替换的包保留进度。司机只查看更新的完整任务、搬运和反馈，不扫码、不改位置、不出入库过账。

## 归属与合同

- 后端归属 `rd-erp-inventory` 的 loading 业务；复用 `PUT /rd/loading-task/exception/resolve` 的 `replacements[]`，不新增表、不重建包号或二维码。
- Web 入口为出库装车任务的异常处理；PDA 入口为 `/pda/warehouse` 的装车视图。二者复用换货清单组件与校验，保留单包、退回、取消、原代表码核验和最终出库。
- 替换货查询复用有权限的在库可选包接口，必须精确匹配包号。查询结果不是库存占用承诺；最终服务端锁定、状态、归属、履约容量和版本校验仍为权威。
- 必填真实处理说明；原包和新码均不可重复。不能替换已核验、已出库或取消的成员，不把畸形码或错误关联变成整任务异常。
- 返回丢失或未读取到真实处理结果时保持待核，不自动重发变更；版本变化必须重读、重新核定，不能沿用旧清单。
- 本轮不擅自变更商务提货数量，不实现未经商务确认的少装减量、客户变更或自动选包。这些属于后续 C5，C5/C6 主项不提前划掉。
