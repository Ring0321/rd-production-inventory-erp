# 瑞鼎生产库存订单 ERP 开发计划

> 状态：原始平台叠加式开发计划已停止执行。本文件用于防止旧模块名、旧目录和演示能力继续进入新代码。

## 当前阶段顺序

1. 安全清洗：失效旧发布包、清理 Git 历史、轮换外部凭据、完成密钥扫描。
2. 数据库瘦身：维护干净基线和幂等升级脚本，升级前必须完成隔离库恢复核对。
3. 后端瘦身：只保留认证权限内核、日志、Quartz 运行内核和 RD 业务。
4. 前端瘦身：只保留 ERP 工作台、RD 页面和精简系统管理页面。
5. 产品能力：维护认证能力接口、ERP 工作台、权限快捷入口和真实业务指标。
6. 验收发布：执行 JDK 17 测试、JDK 21 打包、前端构建、权限检查、备份恢复和安全扫描。

## 开发约束

- 新业务代码进入 `backend/rd-erp-inventory`，包名使用 `com.ruiding.erp`。
- 后端启动模块为 `backend/rd-erp-server`，发布物为 `rd-erp-server.jar`。
- 前端只允许 RD 业务和已批准的系统管理页面进入路由扫描和生产构建。
- 数据库变更必须同步提供干净基线升级说明；不得恢复原始平台 SQL。
- 凭据只能通过环境变量或密钥管理系统注入。
- 不修改外部 ERP，不自动清理生产数据库，不改动原始 Excel。
- 每阶段必须保持可编译、可测试、可回滚后才允许推送。
