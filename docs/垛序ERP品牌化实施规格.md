# 垛序ERP品牌化实施规格

## 决策与范围

2026-10-13，用户要求去掉固定公司的标识，把ERP做成产品品牌，并授权自行创建有特色的名称。产品暂定“垛序 ERP”，简称“垛序”，英文标识DUOXU；定位“生产与仓储协同系统”。名称可统一配置替换，不宣称商标已注册或可注册，也不虚构已拥有的新域名。

源码起点 `6c357d1fb001f152f2026eab9e9dd1cc5e9ca8ba`，工作树干净。继续在原Spring Boot/Security/MyBatis、Vue/Element Plus、MySQL/Redis架构开发，不重写ERP、不扩展多租户SaaS或账号授权。

## 保留与改变

- 改变平台固定品牌：登录页、主框架/折叠Logo、浏览器标题与元信息、启动占位、PDA外壳、追溯头部/页脚、看板及纸质标签品牌。
- 统一产品品牌配置，默认使用新产品标识；不把“天净隆鼎/瑞鼎”变成每个新客户都必须接受的平台抬头。业务企业名应归企业/单据资料，与平台品牌分开。
- 真实客户、供应商、单据抬头、人员、出入库事实、历史附件及原方案书不全库替换、不删除。复用项目的许可证和必须保留的版权/NOTICE不删除；内部包名/表名不为改品牌而破坏兼容。
- 一包一码、原包号及已存二维码URL不重写。对旧码继续本地识别；新标签保留原包件的已存身份。后续新安装/新包的链接域名可明确配置，不假定新品牌已经拥有域名，不擅自将旧标签改域。
- 仓管扫码/库位/过账、司机只搬运，岗位权限和用户会话隔离不变；GLM真实调用仍关闭，原AI外发边界不因品牌调整而扩大。
- 产品的当前业务仍是生产/质检/库存/入出库/追溯，不宣称已具备完整财务、人力、多组织SaaS或正式商标资质。

## 当前下一动作

先实现集中产品品牌配置与新标识，再替换各显示入口和打印抬头；后端支持仅审计固定抬头、种子/部署与二维码存储兼容，不读密钥、不改业务库。最后以实际运行页面和解码/权限/库存证据验证并更新计划。商标、域名和正式对外发布为后续门槛。

后端静态审计已回收并关闭支持任务：原链接构造器要求绝对HTTP(S)地址，新默认采用中性本地开发地址，正式部署显式配置；既有追溯会按新配置重建URL，需优先持久化qrCode。Compose须补传链接变量；新库组织名中性，初始化重复执行和升级不得覆盖既有组织名。客户资料中的企业名、内部rd/com.ruiding标识和第三方许可保留。此结论仅静态审计，尚需实际新库/旧库/重复升级与码内容验证。
