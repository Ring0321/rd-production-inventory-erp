# E4 仓管批次入库与司机免扫码本地验收记录

日期：2026-10-11。分支：`feature/warehouse-pda-next-phase`。本轮统一已确认的岗位分工，补入库侧二维码代表码核验。全部为隔离本地技术验证，样例不是工厂实际生产或检测数据。

## 1. 已交付流程

质检放行 → 仓管选择库位、货物与司机派单 → 司机按目标位置搬运，必要时报异常 → 仓管扫任务内任意一包识别清单 → 勾选实际已经到位的包件 → 批量核验 → 全部核验后仓管确定最终库位并入库。

司机端只显示本人任务、目标位、客户/型号/炉号/炉层、重量、仓管核验进度与异常上报，去除扫码输入、扫码确认和最终入库按钮。使用任务 ID 或包码直接打开本人任务；查询仍由本人接口校验归属。相关异常包通过清单选择，不新增扫码负担。

仓管页新增扫码核验页签，可接受完整数字链接或包号。二维码打开关联任务后会带出该任务所有包件，默认勾选未核验包，仓管可剔除未实际到位包。核验先记录逐包进度，不改变库存或最终位置。最终位置由仓管确认，统一生成入库单、库存批次、库位占用及逐包库存流水。

## 2. 接口、数据与并发

单包 `/rd/putaway-task/scan` 改为仓管确认权限，服务层同时验证；司机的执行权仅用于本人任务读取和异常上报。`START` 与 `COMPLETE_SCANNING` 的执行角色改为仓管；保留 `MOVING` 代码兼容已有记录，界面显示“仓管核验中”。扫码日志类型更正为仓管。

新增 `POST /rd/putaway-task/batch-scan/preview`（查询权）和 `POST /rd/putaway-task/batch-scan/confirm`（仓管确认权）。请求包含代表包、任务 ID、版本、明确选择的明细 ID 和幂等键，不根据生产记录自动扩大到其他任务或库位。

新增 `rd_putaway_batch_scan_record` 保存请求内容摘要、原任务版本、所选明细、数量、操作者、设备和时间，任务与请求键联合唯一。批次加锁后先检查全部选择及包件身份/质检入库状态，再在一个事务中逐包登记，任一失败整体回滚。逐包扫码表继续记录独立包号和实际操作者。整组请求重试返回原记录并新增计数 0；同键内容或操作者不同被拒绝；旧预览版本不能覆盖新计划。

干净基线和幂等升级脚本均增加新表；五张上架表、127 列、21 项命名索引及授权指纹验证通过。升级前保持原备份/隔离恢复规则。回滚必须同步撤回批次接口与页面，保留已登记数据；新表有数据时不能直接删除。旧司机扫码权限不恢复。

## 3. 实际页面及数据库结果

生产记录 8，三包 `LD20261011A0025` 至 `LD20261011A0027`，各 1000 kg，上架任务 1，计划位 `LOC-A-01`；客户/来源/备注均标记“二维码仓管批次入库验证（非现场数据）”。质检值为明确标记的软件验证样例，分人提交和审核。

代表码预览能解析公司数字链接并找到任务、三包清单，预览不写任何扫码。错误代表码被拒绝。先核验一包后任务为 `MOVING`，三包仍为 `INBOUND_PENDING`，库存看板未变化；重复相同请求返回相同记录、新增计数 0；改选内容重用同键被拒绝，过期任务版本被拒绝。

随后实际登录仓管 Web，带包码/任务 ID 打开扫码页，核验剩余两包。数据库为 3 条独立成功扫码和 2 条批次请求，仍未增加库存。点击确认最终库位并入库后，任务为 `PUTAWAY_COMPLETED`，三包在库、位置一致、生成正式入库单及 3 条独立入库流水。没有向真实生产 ERP 或原始 Excel 写入数据。

实际登录司机账号，390/320 px 页面正确打开本人任务；没有扫码输入或入库确认控件，只有任务、进度、货物和异常反馈。小屏没有水平越界，截图已目测。截图和结果保存在 `temp/qr-putaway-verification/`，凭据及测试库不上传。

## 4. 并发、权限与审计复跑

另用生产记录 9、两包 `LD20261011A0028`/`LD20261011A0029`、任务 2，向同一版本同时发送两个不同键的批次核验：1 成功、1 因版本冲突被拒绝，每包 `scan_count=1`。核验后仍待入库，只有仓管最终确认后两包才进入库存。记录保存在 `temp/qr-putaway-concurrency/`。

原 B6 三脚本同步更新并在当前隔离实例复跑：四角色权限通过，司机/审计/只读的单包及批次核验均返回 403；五种操作日志全部成功，仓管 4 条、司机异常 1 条；单包双请求为 1 成功、1 重复，不重复计数。临时测试数据已按限定标识清理。测试支持读取当前实例端口，避免把 3310/6380 的隔离实例错误当作默认端口；修复启动脚本误认退出进程仍在运行的问题，实际重启通过。

库存模块 140 项回归：137 通过、3 项原配置跳过，0 失败/错误；其中批次 6 项覆盖全组、部分、重试、内容冲突、非法包、旧版本及司机拒绝。前端类型/格式/ESLint/Stylelint、生产构建与后端 19 模块打包通过。
