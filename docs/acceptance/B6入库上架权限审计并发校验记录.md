# B6 入库上架权限、审计与并发校验记录

> 以下 2026-09-22 结果保留为旧职责历史。2026-10-11 起扫码核验已移交仓管，当前规格与复跑证据见 `E4仓管批次入库与司机免扫码本地验收记录.md`；不再以旧“司机扫码”作为当前要求。

> 日期：2026-09-22  
> 范围：本地开发环境，租户 1；不等同于工厂现场验收。  
> 责任岗位：仓管、叉车司机、审计、研发；真实人员及业务验收人待指定。

## 校验对象

- 仓管员可查看上架任务、创建派单、处理异常及确认最终库位；司机只能执行分配给自己的任务，不得修改库位或确认库存。
- 审计与只读角色只可查询，不可创建、改派、扫码或确认。
- 创建任务、司机报异常、仓管处理异常、司机扫码、仓管确认均形成可按任务号和操作人追查的操作日志。
- 同一包以不同幂等键同时扫码，只能计入一次；重复请求保留拒绝记录。
- 改派后确认入库时，任务、包、最终库位占用与库存批次保持一致。

## 本地结果

1. 权限脚本 `scripts/security/Test-RdPutawayPermissions.ps1` 通过。仓管、司机、审计、只读四类测试账号的授权与禁止权限均符合预期；允许接口返回业务码 `0`，越权接口返回 `403`。司机的非本人任务隔离另由库存模块服务测试覆盖。
2. 操作日志脚本 `scripts/security/Test-RdPutawayOperationLogs.ps1` 通过。完整执行“仓管派单 -> 司机报库位异常 -> 仓管改派 -> 司机扫码 -> 仓管确认”；同一上架任务共 5 条成功日志、5 种动作、2 位操作人，其中仓管 3 条、司机 2 条。确认后任务和包均指向新库位，原库位占用与预留为 0，新库位占用为 1 包且预留为 0，库存批次数量为 1 包、重量为 1000 kg。
3. 并发脚本 `scripts/performance/Test-RdPutawayConcurrency.ps1` 通过。对同一任务、同一包同时发出两次不同幂等键的扫码请求，响应分别为 `SUCCESS` 和 `DUPLICATE`；任务与明细均只计 1 包，落库 2 条扫码记录且仅 1 条成功。
4. `scripts/verification/Verify-RdPutawaySchema.ps1` 通过。空库初始化、旧库升级、重复升级结果一致；审计和只读角色各有一项上架查询授权，均无上架操作授权。
5. 库存模块完整测试 101 项，0 失败、0 错误、3 项按原配置跳过；后端 19 模块打包成功。

## 修复记录

- 补全仓管创建任务、处理上架异常的操作日志，并在建任务成功后绑定实际任务号。
- 修正锁定查询在租户 SQL 改写后出现的 `FOR UPDATE ORDER BY` 语法问题；库存批次查询已显式约束租户编号，避免重复租户改写破坏 `LIMIT 1 FOR UPDATE`。
- 将审计、只读的上架查询授权写入全新建库和旧库升级脚本，并纳入数据库指纹校验。

## 复跑与边界

上述三个专项脚本仅允许访问本机后端及本机数据库，会创建临时账号和货物，结束时退出令牌并清理测试数据及相关权限缓存。现场验收仍需指定真实仓管和司机、核定库位容量与编码，在实际 PDA/扫码枪上连续扫码并记录网络异常、复测截图、真实单号与岗位签字；这些证据归入 F 阶段，不以本地脚本代替。
