## 五、失败与修复经过

1. 最初权限验收阻止发布：后端把目录节点的空 permission 返回在列表中。实际非空权限均属业务范围。增加回归测试后，仅忽略精确空字符串；空集合、空权限集合、null、空格、系统/基础设施和通配符仍全部拒绝。重新执行沿用原新账号，不重复创建。
2. 首次外网 OCR 上传失败：ERP 网关临时目录被 root 的 nginx 配置校验改属 nobody，而运行用户是 duoxu-erp。定位错误日志的 permission denied，恢复本应用五个临时目录归属。
3. 单独 runuser 校验因没有 443 绑定能力失败，脚本回滚自己的配置且未发送重载信号。最终使用 root 执行独立前缀校验，并显式 `-g 'user duoxu-erp;'`，保持正确临时目录归属；补充断言验证此参数，重新发布及外网 OCR 回归通过。
4. 本机 PowerShell 的 Get-Acl 模块不可加载，凭据刷新先停止，未写入新私有内容。改用 icacls 先限制空备份文件，再写入并复核 ACL；未在终端或聊天打印凭据。

部署单测共 13 项通过，新增用例先失败再修复通过；前端 Node 回归和 `pnpm run audit:prod` 通过，生产依赖无已知漏洞。既有全量开发工具告警和样式问题仍按前次记录保留，不宣称全量 lint 已通过。
