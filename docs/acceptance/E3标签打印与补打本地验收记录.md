# E3 标签打印与补打本地验收记录

日期：2026-10-11。分支：`feature/warehouse-pda-next-phase`。本项推进当前 E 二维码追溯目标，原 C5/C6 进度保留。

## 1. 本轮交付

- 包码库存页支持单包、所选多包、同一生产记录待贴标包件整批打印，每次 1-500 包。
- 标签保留独立二维码、包号、客户、产品/型号、炉号/炉层、净重、生产日期、出炉日期/班次。未登记项显示“-”；不把动态库位印入标签。
- 100×76 mm 标签纸与 A4 使用同一模板，预览与打印共用生成器；小屏预览将二维码与信息顺序排开，完整显示字段。
- 预览、打开打印窗口和取消打印均不改变包件。只有操作者确认标签已全部成功输出后，才登记本次打印。
- 单包和批量首次打印均只允许待贴标包。后端按 ID 顺序加锁，先检查全部选择再逐包更新，任一包无效则整组拒绝，事务失败时整体回滚。
- 补打必须有原因；已贴标及后续未作废状态均可补打。补打追加逐包日志，不修改原包号、二维码、库位或库存状态。
- 打印与补打分别复用现有 `rd:label-print:print`、`rd:label-print:reprint` 权限。首次登记的重复请求被状态校验阻止；重印不是自动网络重试，不隐式重复登记。

接口：`POST /rd/package-unit/print-batch`、`POST /rd/package-unit/reprint-batch`。请求明确传入本次实际打印的包件 ID，不能仅给生产记录 ID 就自动登记所有货物；单包旧接口保持可用并复用相同校验。

## 2. 样本与输出核对

模板校验样本为 10 张明确标记的本地示例，覆盖上层/下层、1000 kg/697 kg、较长客户名称及班次日期。逐张核对客户、型号、炉号、炉层、生产日期、班次、包号、重量。标签纸 PDF 为 10 页；A4 PDF 为 2 页（8+2 张）；全部 10 个包号各出现一次，无空白多页、缺包或重复包。

独立 OpenCV 解码器核对 10 个原始二维码及 10 页标签 PDF 按 300 dpi 渲染后的二维码，20 次全部还原为对应 `https://id.tjldsic.com/pkg/{packageCode}`。这里只证明二维码内容和打印输出文件可识别，没有验证实体标签材料和实际打印设备。

HTML 字段经过转义，恶意客户名称作为文本展示，不执行其中的 HTML。打印版边界检查及 390/320 px 预览检查通过。

## 3. 实际 Web 与数据库核对

在既有隔离 `patent` 本地实例启动当前后端 JAR 和前端正式构建。使用生产记录 5，客户为“本地标签验证示例（非现场数据）”，来源为“E3 本地技术验收”；10 包为 `LD20261011A0011` 至 `LD20261011A0020`，各 1000 kg。没有修改其他历史货物或真实生产 ERP。

按实际 Web 页面操作：内部登录 → 包码库存 → 同生产记录整批打印 → 显示 10 包及标签预览 → 打开打印页 → 模拟确认成功 → 查看逐包状态 → 再次提交相同首次打印请求 → 补打缺少原因拒绝 → 单包填写破损原因补打 → 回查状态。确认前，数据库打印记录为 0；首次确认后为 10，全部包状态为 `LABELED`；重复首次确认被拒绝，记录仍为 10；缺少原因的补打被拒绝；有效补打后总记录为 11，其中补打为 1，原包号与状态未变化。

这是本地模拟“打印成功”确认的业务测试，未调用实体打印机。测试记录与测试样本保留为技术核对证据。

浏览器在 1440、390、320 px 运行，无页面执行异常。实测发现并修复共用 Dialog 自定义标题未关联 `titleId`，以及缩窄后标签弹窗越界和信息被二维码挤成竖排的问题。最终小屏截图经目测，字段、二维码、包号和按钮完整显示；自动断言检查弹窗边界及标签整体位于预览区域。

## 4. 可复跑验证

后端定向 `RdPackageUnitServiceImplTest` 8 项通过，覆盖逐包日志、整组拒绝、加锁次序、补打状态保持、原因校验、重复 ID 与作废包拒绝以及原追溯字段隔离。库存模块完整回归共 125 项，122 通过、3 项按原配置跳过、0 失败、0 错误；后端 19 模块打包成功。当前 Java 21 环境需要 `-DargLine=-Dnet.bytebuddy.experimental=true` 兼容既有 Mockito/Byte Buddy；没有放宽业务断言。

前端类型检查、修改文件的 Prettier/ESLint/Stylelint 与生产构建通过。非阻断构建提醒为既有 Browserslist 数据过期与插件耗时提醒。

软件输出校验脚本：

```powershell
rtk node scripts/verification/Verify-RdPackageLabels.mjs
rtk python scripts/verification/Verify-RdPackageLabelPdf.py
rtk node scripts/verification/Verify-RdPackageLabelRuntime.mjs
```

依赖：Node 前端依赖、Playwright 与已安装浏览器；Python 的 OpenCV、PyMuPDF、NumPy。Playwright 不在前端依赖目录时通过 `RD_BROWSER_MODULES` 指向已配置的依赖目录；系统 Edge 可指定 `RD_BROWSER_CHANNEL=msedge`。脚本使用本地 `temp/local-runtime-patent/.env.local`，也可通过 `RD_ERP_ENV_FILE` 指定隔离实例；不把凭据写入验收记录或 Git。

运行时脚本默认新建明确标记的 10 包示例。使用 `RD_QR_LABEL_PRODUCTION_ID=5` 和 `RD_QR_LABEL_UI_ONLY=true` 可只复测已有示例的小屏页面，不重复登记或新增样本。默认完整测试必须使用未打印的本地样本。

生成证据保存在 `temp/qr-label-verification/` 与 `temp/qr-label-runtime-verification/`，含 HTML、PDF、二维码原图、截图和结构化结果。这些输出被 Git 忽略，代码库保留脚本及本记录；凭据和启动原始日志不上传。
