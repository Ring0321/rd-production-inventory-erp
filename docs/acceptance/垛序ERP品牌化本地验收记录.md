# 垛序 ERP 品牌化本地验收记录

日期：2026-10-13，Asia/Shanghai。源码起点6c357d1；执行研发，业务签字负责人待指定。本次是产品品牌化的本地软件与验证包检查，不是商标注册、正式域名、实体设备、现场或多组织SaaS验收。

## 一、实现范围

用户要求去掉固定公司标识，并授权自行创建有特色的品牌。命名“垛序 ERP / DUOXU”，定位“生产与仓储协同系统”。使用生成并复制到项目内的透明PNG标识，统一名称、简称、副标题、图片和初始HTML配置；登录、主框架、页脚、看板、PDA、追溯及纸质标签固定厂标退出运行入口。

产品品牌与客户组织、客户/供应商、人员、真实单据和货物事实分开；旧包号及持久化qr_code不重写。新本机链接默认localhost:9000/pkg，正式部署显式配置实际可达地址，不能称为已经注册的品牌域名。缺失历史URL的预览只能从后端追溯读取，不从浏览器/前端配置猜地址。技术包名、表名和复用框架许可不删除、不随改名破坏接口。

## 三、复核与修复

后端静态清单、PowerShell诊断、独立品牌复核均已回收并关闭支持任务。复核发现缺失二维码时前端origin与后端显式域名不一致，已改为原追溯接口权威解析并实测；没有把扫码兼容称为原公网域名已可达。

旧码重建先被前后端测试复现并修复。数据库预期两次误报转交新上下文，证明PowerShell5/CP936误解无BOM脚本中文，改用正确UTF8字节的ASCII常量后原断言及所有迁移检查通过；未改SQL绕过失败。品牌模块新增依赖使三项旧测试缺少边界模拟，补齐品牌边界后全部通过。浏览器第一次误比PNG压缩字节改为码图模块，未放宽“原码内容一致”。一次UI_ONLY参数误写1时原检查拦截重复打印，纠正为true后通过。工具引号/补丁上下文失败不作通过证据。
