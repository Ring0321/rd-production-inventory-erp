# 二维码作业增强本地验收记录

日期：2026-10-15。产品：垛序 ERP。实施基线：11c7809899301012264df5b6d0d2f156a42eb413。研发执行已完成；工厂业务验收人待指定。本记录仅为本地软件验收，不是现场签字验收。

## 1. 本轮交付

1. 可视化连续扫码：仓管 Web/PDA 上架、装车原流程内增加扫码工作区；相机连续识别、本机多码图片识别和键盘采集共用精确成员分类。绿色本任务、黄色重复、红色错包/不可用；去重计包，重量来自实际登记值，包含非整吨尾包。核对后仅带回所选清单，仍由仓管点击原核验和最终过账。
2. 货物追溯关系图：内部包件追溯页增加 G6 图，默认当前包业务主线，可展开全部真实历史；选择质检记录时展示实际覆盖包子图及样包/非样包标识。连接来自生产外键、质检成员、上架/装车行、任务事件、出库明细和库存流水；库位节点按登记 ID 跳到原 3D 空间，不猜测坐标或炉号关系。
3. 本机待同步箱：Dexie 仅用于 IndexedDB，本机按用户、租户、任务和操作隔离。保存包码、原观察版本、时间和候选状态，拒绝额外身份字段；断网保留候选，恢复后显式核对权限、任务版本及成员状态。PDA 首页提供任务总览和原任务入口，离线候选从不自动形成库存。

原一包一码、稳定数字链接、Nayuki 标签生成、批次代表扫码和司机只搬运不扫码的责任边界保留。不加 OCR、签名防伪、云数据库、自动定位、自动数吨袋或 GLM 外发。

## 2. 数据与权限

新接口仅 GET /rd/package-unit/relations?packageCode=...，登录、包件查询权限和租户边界由服务器执行，各领域仍要求其原查询权限。未授权领域不查询、不回传隐藏总数。每领域限制 100 条，图限制 500 节点/1000 连接，受限、缺失和截断明确说明。

真实质检覆盖和样包标识不能从代表包或同炉号推断；现代记录部分缺成员时返回 INCOMPLETE。历史库位快照不是当前占用，旧装车成员不继承新包的出库状态。公开护照不请求内部关系接口；执行型司机无新增包件查询授权。

身份代次变动立即清屏、销毁图和停止相机；异步守卫直接检查当前代次。原未决写请求优先于候选箱：Web/PDA 共用原请求持久化/核定语义，丢失响应后不能替换成员或生成新幂等键。重放回执可报告零新增计数，但必须与原请求 APPLIED 状态和记录 ID 一致才能结束待核。
