# 二维码链接深化本地验收记录

日期2026-10-13，源码起点976cd5731431148a577df0ddf827441b52e8c58a。执行研发；业务签字人待指定。专项覆盖GitHub技术取舍、稳定包码到自有多资源、公开快照和本机核对；不是正式部署、真实GS1/DPP、签名/防伪或现场验收。沿用垛序ERP1.0.0＋Git提交策略。

## 实现与职责

原二维码、独立包号、已存qr_code、打印/补打及角色流程保留。新公共服务仅复用getTraceDetail(code,false)并明确投影，内部页也不能把私有trace导出成公开快照。快照不含客户/库位/单据/人员/内部ID/自由备注/检验测值/附件；待核保持未知，登记重量不是实磅。摘要只校验canonicalJson的UTF-8字节，不含每次读取时刻；相同内容查询不制造数据变化。

同/pkg地址默认原网页；resource或Accept选择公开JSON、JSON-LD或RFC9264式Linkset。原身份作anchor，资源地址来自本机/自有服务器受信配置，不使用请求Host或任意next跳转。新base路径段和包码有结构边界，历史身份只读保留。Nginx/本地入口对整个公开前缀固定组织、去登录/访问组织头并在转发前拒绝查询登录。内部API规则不改；无出入库、库位或质检写接口。

页面下载独立公开文件，本机检查大小、schema、包码、公开字段及SHA-256，再由用户明确核对服务器当前公开记录。文件留本机，不执行文件URL，不上传附件；重算摘要只表示字节自洽，服务器不同不自动判断假货。掉网或不支持WebCrypto明确未核实。仓管仍扫码/选位/过账；司机仍只按任务搬运/反馈。

## 复核与修复

独立只读复核发现：部署缺组织头、不同表示共享ETag、点号新base无法被入口识别、web捷径绕过重复参数；均已补复现/测试修复。第二次发现非规范包路径绕过公开头策略、query token与visit-tenant-id可影响组织；主任务实际复现后覆盖整个公开前缀，拒绝非规范查询并去访问组织头，17/23项最终重跑通过。未改底层全局登录/租户框架或降低投影断言。

主任务最终检查另外复现本地代理会解释绝对形式请求的主机：指向本机未监听端口的绝对请求返回502，而不是既定后端。改为仅从请求取path/search并固定配置的后端origin，实际同一请求正确返回公开快照；最终18项本地请求包含此回归，不向外站发测试请求。

Nginx原生验证器初次缺mime相对路径及temp父目录，修正隔离测试环境后测试通过；新增查询正则一度覆盖包码捕获，实际500复现后先保存包码再做参数校验，最终同模板通过。前端新增测试初次错误预期异常文本，核对已有明确错误后修正文本断言，保留拒绝断言。失败结果不作为通过证据。

研究/复核结果和支持状态保存在专项规格：研究回收；容量失败的后端支持无文件产物，主任务接管；两次只读复核均回收关闭。没有复制外部项目源码/依赖，现有许可证保留；只借鉴持久身份、多资源及可核验内容行为。
