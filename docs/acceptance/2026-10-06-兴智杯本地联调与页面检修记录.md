## 2. 本轮检修

| 问题 | 原因与改动 | 核对方式 |
| --- | --- | --- |
| 业务日期出现数组或逗号日期 | 前端包码页兼容数组日期；后端 LocalDate 明确采用 ISO 年月日序列化，保留事件时间戳合同 | 两项回归先失败再通过；入库、生产、标签与追溯实机显示 2026-10-05 |
| 完成装车任务无法明确回查，预览错误后仍显示旧结果 | 支持路由中的明确 taskId；相同代表码优先保留已知任务上下文；失败清理预览及选择；OUTBOUNDED 明确只读 | 本地任务回查显示 2/2，两条明细已出库，确认和过账按钮禁用 |
| 已审核通过的追溯页仍显示已送检 | 前端仅识别 PASS/REJECT，与当前 PASSED/REJECTED 状态不一致；统一兼容两组状态值 | 后端 PASSED，追溯页显示合格，历史事件保留原审核事实 |
| 已出库仍标为当前库位 | 包件保留历史位置以供追溯；前端按 OUTBOUNDED 显示出库前库位及已离库说明 | 内部与公开视图均核对；批次位置说明包含历史 |
| 无效包码仅显示服务器 500 | 统一异常处理器缺少 RestControllerAdvice 注册；恢复控制器异常 JSON 响应，保留业务错误码与提示 | 两项 Web 响应回归先失败后通过；实机提示包码不属于当前任务，旧任务及选择清除 |

## 3. 数量与权限结果

初始总库存 18 包、18000 kg；两包入库后 20 包、20000 kg；同两包出库后回到 18 包、18000 kg，订单锁定 0。两条装车明细关联正式出库单和库存流水；示例订单保留 1 包剩余需求。第一次代表码确认 2 包，相同请求重放新增确认 0 包且返回原记录。

内部追溯包含身份生成、质检提交、质检复核、入库和出库五个事件；公开接口不返回客户、内部库位、生产记录编号、操作人员或内部单据细节。司机可读本人任务，调用仓管代表码预览返回 403。上述为本轮定向核验，不替代 C6 完整角色与并发矩阵。
