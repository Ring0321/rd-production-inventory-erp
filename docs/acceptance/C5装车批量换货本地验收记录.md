# C5 装车批量换货本地验收记录

## 范围和环境

验收日期2026-10-12。对应总计划C5、实施规格 `C5装车批量换货实施规格.md`。已提交起点 `c8ee2b3`，本轮源码、重新打包的 `rd-erp-server.jar` 与 `frontend/dist-prod` 在隔离 `patent` 本地实例验证。MySQL3310、缓存6380、后端48080、页面9000；不记录或提交本机凭据。

试用入口为 Web“出库装车 → 装车任务 → 处理装车异常”，以及 `/pda/warehouse?section=loading`。本轮客户、订单、车辆和包件均为标明“非现场数据”的验证样本。工厂尚无打印机/PDA/扫码设备，本轮不等同于实体打印、现场实扫、正式域名或岗位签字。

## 已观察结果

- Web和仓管PDA使用同一多包清单；可核对每个替换包的实际客户、型号、炉号、炉层、位置和净重。一次最多100包，仍是一张完整装车任务，不拆司机小组。
- 精确包号条件在服务端过滤，不以100条模糊结果的第一页代替包号定位；客户端仍核对返回身份、状态和货物资料。停留在库可选包不意味着已为本任务占用，提交时重新校验和锁定。
- 两个原包、两个替换包不能重复。已核验/出库/取消成员不能换货；畸形关联不转为整任务异常。真实版本、账号、租户、页面生命周期和确认时的完整清单固定，离页再回不能继续旧确认。
- 服务端先准备完整候选计划，再核定提货单/各明细批准包数与重量、含保留成员的聚合履约量、库存批次实存及订单锁定量。不同单包重量可以组合保持批准合计，不能默认改变商务发货量。
- 替换成功时，旧包释放装车占用但仍在原库位、保留原二维码；新包等待仓管实际核验，未替换的已核验成员保留进度；每对换货写关联的换出/换入历史。
- 实际MySQL第二个新占用写入失败时，异常关闭、占用、明细、计划版本和已写历史整笔回滚。真实聚合履约不足、第二包资料不符以及司机/销售越权均拒绝，不改变该任务业务指纹。
- PDA实际完成两包换货后，自动使用任务内新代表码继续核验，最终3包/2800kg出库，内部生成两张库存出库单，但司机只接一张完整装车任务。两包旧货继续在库；司机本人端看到更新资料且无扫码、位置修改或最终过账控件。
- Web实际两包换货发生同版本双请求争用，仅一个成功、另一个返回版本冲突；主动丢弃原请求响应后，页面显示持久“装车异常处理结果待核”，禁用重复提交，不报成功。明确重新读取显示真实已调整任务。
- 320/390 PDA、1440 Web截图已实际查看；Web多包表单复用原弹窗滚动与高度约束，标题和确认按钮留在屏幕内。截图等待确认浮层关闭，避免用过渡帧代替稳定页面。

## 复核与修复

两独立只读复核均接收结论并原生关闭。第一轮指出整计划数量、批准重量、库存容量和输入上限缺口，已补先校验后写入；第二轮指出离页返回后旧确认继续、精确包被模糊分页遗漏，两端及候选预览均补代次保护，库存查询增加向后兼容的 `packageCode` 精确条件。四项新增源码回归先失败再通过。

测试脚本修复保留在实施规格：CLI多语句触发器改为仅命中隔离第二包的单语句约束故障；按输入控件真实列表ID定位重名下拉框、按业务区域定位二维码输入、补Web文本框可访问名称；等待实际请求失败事件及关闭动画后核验，不把提交中禁用误判为结果待核。
