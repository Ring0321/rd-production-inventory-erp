## 请求与数据安全

- 装车核验必须携带服务器任务版本，避免换包保留明细 ID 后旧清单误确认新包。
- 原请求摘要绑定登录操作人、任务、原版本、规范化代表码及排序成员，原键不能换账号、换内容或换版本重放；合法重试在当前状态/版本判断前返回原结果，新增计数为零。
- MySQL 实际拒绝换包前旧版本；实际重放成功，同时拒绝管理员换账号、改变成员和改变原版本，原任务时间/计数/版本不变。
- 定向 MySQL 触发器让新扫码记录写入失败，整任务、成员和实际包的 LOADING_SCAN 历史计数保持原值；同请求健康重试后只登记一次。测试触发器在 finally 删除，终态核对为零。
- 已完成最终出库从持久出库单关系恢复五包/4600 kg，原任务确认时间与版本不变，库存不重复扣减。
- 新摘要列为可空 CHAR(64)，新库/旧库升级/重复升级均通过；旧夹具记录未改写，旧摘要保持空，不编造原请求成员。
- 可见的库位图、库存台账和 PDA 库位每五秒只读核对，隐藏/卸载/停用/换身份或租户不应用旧结果；未提交筛选不被后台查询。重新激活不重叠未完成读取。

## 复核与失败历史

后端独立复核指出版本、请求绑定、最终结果恢复与长度约束问题，已先复现再修复。独立前端复核指出弹窗目标可变、骤然刷新歧义、非响应式上下文缓存、停用后读取重叠、失败报成功及 query-only Enter 触发 preview；实际源码新增七项失败及 Web 三项失败，修复后对应检查通过。三个支持上下文均已接收结果并原生关闭，不复用。

浏览器早期失败有明确夹具/观察原因：点击透明 input 改为实际可见下拉 wrapper（未用 force）；等待待核按钮不足以证明服务器已提交，改为响应成功信号再断开；测试资料缺订单履约，补齐商务销售订单及真实库存批次分配；装车原因使用实际 WRONG_PACKAGE；小屏 Web 导航收起，台账改用实际路由并以桌面宽度验证；匿名跳登录改等待实际路由完成，没有删除登录断言。失败日志及 DOM/截图在本机 temp 中保留。

## R11/R12 本轮补齐

服务端增加与原 confirm 使用相同请求/权限的 `/rd/putaway-task/batch-scan/status`、`/rd/loading-task/batch-scan/status`。同真实操作人和内容的持久记录才 APPLIED；无记录且当前版本严格高于请求版本才 NOT_APPLIED_STALE；同版本或未来版本无记录保持 UNKNOWN。PDA 显示核定入口，UNKNOWN、失败和取消保留原待核；APPLIED 读取当前真实任务后恢复；明确旧版未执行须仓管确认后结束本机待核、重新选实际成员，不产生业务撤销或最终过账。

独立只读复核接收后即时关闭，三项新问题先复现：前端旧页重试/新捕获覆盖四项及未来版本一项失败，后端当前读/未来版本四项失败；修复后全部通过。持久写入和清除均核对原内容，冲突不覆盖较新待核；会话核对当前登录缓存，另一标签注销/换账号后旧操作不能继续；任务之后的原键记录 FOR UPDATE 当前读，不受权限查询先建快照影响。没有新表、服务、角色授权或历史摘要回填。
