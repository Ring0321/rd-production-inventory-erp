# E3 生产任务打印与生产 PDA 实施规格

## 对应计划

补齐总计划 E3“按生产任务批量打印”的 D2 依赖，沿用 E1 编号与 E5 追溯。基线 `f18a10486676920e4734bbc3068d4398fa8d6c33`。上一轮为有效进展：完整追溯、事务回滚、内外视图与回归已在该源版本验证。

本轮不开发采购、BOM、订单强制关联或新库存账，不把“生产记录”改名后冒充独立任务。

## 业务约束

- 班长创建任务：客户、业务生产日期、班次、备注；任务号由服务器生成，不要求订单、合同。
- 一个任务可有多条实际产出记录，型号、炉号、炉层和单包重量可不同。客户、业务日期、班次由任务带入，出炉日期可按实际补录，不补造。
- 生产 PDA 选择任务后填写型号、炉号、炉层、包数、单包重量。录入人由登录身份记录；生产不登记最终库位，库位仍由仓管确定。
- 包数按实际整包数登记；尾包不同重量另建一条同任务产出记录，不按 1 吨推算真实净重。
- 创建产出为草稿，确认后才生成一包一码。打印成功由操作者另行确认，才写首次/补打记录；取消打印不写记录，不额外要求工人扫码。
- 包件固化任务 ID、任务号和产出 ID。一个任务不等于一个质检/入库批次；既有代表码核验仍定位当次实际上架/装车任务，不将同生产任务全部包自动过账。
- 任务 `ACTIVE` 可登记；任务信息只在没有有效产出时可改。`CLOSED` 表示生产登记结束，须已生成实际包件，不表示质检、入库或发货完成。`CANCELLED` 只允许没有有效产出的任务，保留历史记录。
- 已关联的产出不能换任务；已生成包件的产出不能改客户、日期、炉层或重量。已有无任务历史记录不补挂虚构任务。
- PDA 提交携带请求 ID，重复请求必须绑定同一内容与录入人；重试返回原记录，不产生重复产出/包码。不同任务或不同内容复用请求 ID 被拒绝。
- 任务、产出、包生成均按“任务锁在前、产出锁在后”访问，防止结束登记与新录入/生成包并发穿透。

## 接口约定

任务对象：`id, taskNo, productionDate, customerName, shiftCode, status, version, managerId, managerName, closedTime, cancelledTime, remark, createTime`。

- `GET /rd/production-task/page`：分页，按任务号、客户、状态查询。
- `GET /rd/production-task/get?id=`：对象。
- `POST /rd/production-task/create`：客户、生产日期、班次、备注，返回 ID。
- `PUT /rd/production-task/update`：同字段加 ID/版本，须无有效产出。
- `PUT /rd/production-task/close`、`/cancel`：ID/版本。
- 产出沿用 `/rd/production-output`，新增 `productionTaskId, productionTaskNo, shiftCode, furnaceOutDate, operatorId, operatorName`；创建另有 `clientRequestId`。旧客户端不传任务仍按既有流程工作。
- `GET /rd/package-unit/task-packages?productionTaskId=`：精确任务包清单，不用分页第一屏猜测范围。
- 批量打印/补打沿用既有接口，新增可选 `productionTaskId`；携带任务时，服务器校验本次实际打印包全部属于该任务。每次 1-500 包，不能因只取第一屏而漏包。
- 公开追溯不暴露任务/操作人；内部追溯补任务引用，标签保留真实任务与班次信息。稳定二维码地址不改变。

## 界面与权限

Web 新增“生产任务”，PDA 新增“生产录入”。PDA 为任务选择、紧凑录入、确认/包码生成和标签入口，不依赖后台复杂筛选，不要求手输任务 ID。

任务查询/新增/修改/结束/作废采用 `rd:production-task:*`，生产角色有办理权，管理/只读仅查询。原标签、包生成、产出权限继续由各自服务校验；仓管、质检、司机不因本项得到生产管理权。

新页：`rd/production/task/index`，路由名 `RdProductionTask`；`rd/pda/production/index`，路由名 `RdProductionEntry`。PDA 标签入口带 `productionTaskId` 至现有包码打印页，保持已有打印模板和确认机制。
