# 小垛业务问数指标与权限合同

版本：S1-01 / v1。日期：2026-10-22，Asia/Shanghai。

## 1. 本次交付边界

已经实现 `RdWorkQueryContract` 和 `RdWorkQueryAccessPolicy`，并通过合同、服务端鉴权及近邻业务回归。它们是后续只读查询共用的内部边界，不是已开放的业务接口。

本次没有增加 Controller、数据库查询器、数据库迁移、扫描任务或前端按钮。`GET /rd/work-assistant/query` 尚不存在，Q01-Q08 的真实查询由 S1-02 至 S1-04 接入；Q09/Q10 在策略层始终返回业务码 503，包括管理员。不能把枚举已定义理解为功能已上线。

原一包一码、仓管扫码和最终确认、司机仅搬运与反馈的职责不变。DeepSeek 仍沿用原字段白名单与 20 元/月预算；本模块不依赖模型客户端、不发出模型请求。

## 2. 查询与权限矩阵

所有查询先通过真实登录身份及租户检查，再判断权限。表中权限为逐项 AND，不是多项 OR。`ADMIN` 用户类型表示 ERP 后台人员身份，不表示超级管理员角色。

| 编号 | 事实来源与筛选口径 | 指标键 | 最低读取能力 |
| --- | --- | --- | --- |
| Q01 当前台账库存 | `rd_stock_lot`；当前租户、未删除、`AVAILABLE/LOCKED` 且 `warehouse_qty > 0`；当前快照，不是历史库存 | `LEDGER_IN_STOCK_QTY`、`LEDGER_AVAILABLE_QTY`、`LEDGER_LOCKED_QTY`、`REGISTERED_WEIGHT_KG` | `rd:dashboard:query`；司机禁止 |
| Q02 今日流水 | `rd_daily_stock_summary` 的服务器上海自然日 `biz_date`；沿用原流水计算器的正反向口径 | `INBOUND_QTY`、`OUTBOUND_QTY`、`NET_CHANGE_QTY` | `rd:dashboard:query`；司机禁止 |
| Q03 待检包件 | `rd_package_unit.status = QC_PENDING`；主键去重；不是 DRAFT 或 SUBMITTED 质检单数 | `DISTINCT_PACKAGE_COUNT`、`REGISTERED_WEIGHT_KG` | `rd:package-unit:query`；司机禁止 |
| Q04 质检待复核 | `rd_quality_inspection.status = SUBMITTED`；提交时间和真实 `rd_quality_inspection_member` 成员；无覆盖记录不能扩展到同炉或整批 | `BUSINESS_OBJECT_COUNT`、`DISTINCT_PACKAGE_COUNT` | `rd:quality-inspection:query`，沿用原质检详情/覆盖范围权限；司机禁止 |
| Q05 合格待入库 | `rd_package_unit` 的 `QC_PASSED` 与 `INBOUND_PENDING` 分开；已派任务不等于已入库 | `DISTINCT_PACKAGE_COUNT`、`QC_PASSED_PACKAGE_COUNT`、`INBOUND_PENDING_PACKAGE_COUNT`、`REGISTERED_WEIGHT_KG` | `rd:package-unit:query`；不凭此权限读取完整上架任务；司机禁止 |
| Q06 上架待办 | 原上架任务及真实任务行；保留 `PENDING_PUTAWAY/ASSIGNED/MOVING/PENDING_CONFIRMATION/EXCEPTION_PENDING` 阶段，不包含完成/取消任务 | `BUSINESS_OBJECT_COUNT`、`DISTINCT_PACKAGE_COUNT` | 全局读取需 `rd:putaway-task:query`；本人任务需 `rd:putaway-task:execute` |
| Q07 装车未出库 | 原装车任务及真实任务行；`PENDING_ASSIGNMENT/ASSIGNED/LOADING/PENDING_REVIEW/EXCEPTION_PENDING` 不算已出库 | `BUSINESS_OBJECT_COUNT`、`DISTINCT_PACKAGE_COUNT` | 全局读取需 `rd:loading-task:query`；本人任务需 `rd:loading-task:execute` |
| Q08 装车占用 | 实际 claim + 同租户原装车任务 + 实际包件；只读占用不等于异常，不根据炉号推断关联 | `BUSINESS_OBJECT_COUNT`、`DISTINCT_PACKAGE_COUNT`、`REGISTERED_WEIGHT_KG` | 同时需要 `rd:loading-task:query` 和 `rd:package-unit:query`；司机禁止 |
| Q09 待处理提醒 | 将来的提醒投影与扫描健康；只统计当前有权读取的对象 | `ALERT_COUNT`、`BUSINESS_OBJECT_COUNT`、`DISTINCT_PACKAGE_COUNT` | 预留 `rd:work-alert:query`，还须原来源权限；当前全部禁用 |
| Q10 单条提醒解释 | 精确 `alertId` 的投影、事件及重新核对的实际来源；规则命中事实不推断真实根因 | 同 Q09，详情是一条提醒 | 同 Q09；当前全部禁用 |

Q04 的质检成员可见性来自原质检 `/scope`、`/get` 的读取能力，不以此授予独立包码追溯、全仓查询或质检审核权限。查询中需要额外来源时，必须单独核对能力并扩充合同，不能悄悄关联完整客户、订单或库位数据。

Q08 包件主键去重，任务数按 taskId 去重；终态任务的残留 claim 不应被静默丢弃或自动释放，后续规则另行评价。Q06/Q07 全部任务的计划/完成数量属于各自任务明细，跨任务不同主键或重复成员不能相加冒充独立包件数。

## 3. 数量、重量与日期

### 3.1 不混用台账数量与逐包计数

- `LEDGER_PACKAGE_QTY` 是原库存台账的包当量，支持六位小数；Q01 不是 `COUNT(package_id)`。历史导入的小数不能取整、抹零或伪装成已逐包核实。
- Q01 可用量沿用逐库存行 `GREATEST(warehouse_qty - COALESCE(locked_qty, 0), 0)` 再汇总。台账锁定量不等于装车 claim 数；若账、码或锁定来源矛盾，应返回部分/待核而不是修改原数量。
- `PACKAGE` 是包件实际主键去重后的非负整数；`BUSINESS_OBJECT` 是实际质检单或任务数；`ALERT` 是提醒条数，三者不同。
- 重量单位为 `KG`，使用服务器 `BigDecimal`，最多保留原库六位小数，标注“登记重量”。不得冒称磅秤实测或未经核实的重量。
- 所有数值在 JSON 中输出十进制字符串，`unit` 由固定指标键确定，不允许浏览器自行指定。避免大整数和重量转换成 JavaScript 浮点数后丢失精度。

### 3.2 今日出入库沿用已确认原口径

Q02 入库量按原计算器统计 `PRODUCTION_IN/INBOUND` 的有符号 quantity；出库量为 `OUTBOUND` 的 quantity 取反。反向 OUTBOUND 会抵减出库量，因此出入库汇总指标可以为负，不能截断成零。净变化为有效原流水 quantity 的总和，还包含调拨、退货与调整，不能简单写成“入库减出库”。

原入库撤销使用 `ADJUST_OUT`、`source_type = INBOUND_ORDER_REVERSE` 并关联原流水。按现有日报口径，该撤销影响净变化，不自动扣减 `inbound_qty`。本轮不改写原报表，不同时删除原流水又叠加反向流水；需要“业务净入库量”时另定义新指标。草稿单、未过账任务和仓管待复核不能计为已入/出库。

`BusinessDay.today(Clock)` 固定按 `Asia/Shanghai` 计算自然日，区间为 `[当天零点, 次日零点)`，不依赖操作系统或测试 Clock 的默认时区。Q02 返回 `businessDate`；其他查询不带历史日期。请求不支持 `asOfDate/startDate/endDate`，历史问题引导原报表。

## 4. 请求合同

未来 HTTP 适配器必须把完整多值参数传给 `Request.parse(Map<String, List<String>>)`，不能先压成单值 Map。构造器同样校验，内部直接创建 Request 也不能绕开。

| 字段 | 约束 |
| --- | --- |
| `queryType` | 必填，严格为 `Q01` 至 `Q10`，不接受 SQL、自然语言、别名或脚本 |
| `warehouseCode` | 可选，精确编码，不用同名简称；不超过 64 字符，无空值、首尾空白或控制字符；当前策略暂不支持任何分仓组合，传入即返回业务码 400，不降级为全局结果 |
| `alertId` | 只允许且必须用于 Q10，正 Long；Q10 不再叠加 warehouseCode |
| `pageNo` | 默认 1，范围 1 至 10,000 |
| `pageSize` | 默认 20，范围 1 至 100 |

Q01/Q02 为摘要、Q10 为单条详情，只接受默认分页值；其余查询按主对象分页。数字必须是规范正整数字符串，不接受符号、小数、科学计数法、前置空白或“全部”。任何未知字段、重复参数、空参数均拒绝。

不接收 `tenantId/userId/driverId/role/permissions`，也不接收模型、URL、SQL、原问句或任意时间段。服务端从安全上下文获取身份，前端菜单只用于展示，不是鉴权依据。

## 5. 响应合同

`Result<T>` 包含 request、scope、asOf、businessDate、quality、metrics、items、total、sources、notices。

| 字段 | 含义及不变量 |
| --- | --- |
| `scope` | `TENANT_AUTHORIZED`：原业务在当前租户内授权范围，不承诺额外部门/客户/仓库隔离；`OWN_TASKS`：仅当前人员实际被指派的任务，只能用于 Q06/Q07 |
| `asOf` | 数据读取快照时刻，由真实读取事务提供；不是浏览器接收时间、不是所有记录最近更新时间；无可用事实时为 null |
| `metrics` | 当前查询固定键集；每项含 key、unit、quality、value、reason；不能增加别的查询的指标，也不能把未知值补成零 |
| `items` | 查询专用、经筛选的只读 DTO；不直接序列化数据库实体，不使用模型生成对象；列表容器不可修改 |
| `total` | Q03-Q09 的主对象授权总计，与该查询 totalKey 一致；不是本页条数，来源不完整时必须 null；摘要与 Q10 必须 null |
| `sources` | 固定来源枚举及可用 revision；可靠版本不存在时 revision 为 null，不编造版本；重复或越出本查询的来源拒绝 |
| `notices` | 对部分/未知结果说明原因；不回显 SQL、数据库错误、密钥或其他账号对象信息 |

三态有严格区别：

1. `KNOWN`：全部必需指标和来源齐全；数字可以是真实的 0。分页总计与当前页窗口一致，且计数指标等于 total。
2. `PARTIAL`：必须给出原因，有源快照，不能声称精确总计；指标分别保留已知、部分和未知，已读子集不能冒称全量。
3. `UNAVAILABLE`：所有指标数值为 null，items/sources 为空，total/asOf 为 null，并给出原因。绝不以空列表表达“确认为零”。

Q03/Q05/Q08 的 total 按独立包件；Q04/Q06/Q07 按质检单/任务；Q09 按提醒条数。distinctPackageCount 是另一项全范围聚合，不得用任务行数、当前页成员数或提醒条数替代。

`revision = null` 不代表源业务没有版本，也不代表可忽略原页面版本检查。读取适配器必须保留实际可取得的业务版本和成员来源，后续动作仍回到原页面重新核验。

## 6. 服务端权限与范围

1. 必须为已认证的 ERP 后台人员，有有效用户和租户；拒绝未认证、前台会员、缺租户、忽略租户模式，以及登录租户和当前租户不一致的访问。即使原框架跨租户访问会跳过部分权限，本模块也不使用该豁免。
2. 实际持有 `rd_forklift_driver` 的账号先进入司机分支，即使叠加管理角色或通配权限也不得全仓问数。Q06/Q07 分别核对 execute 能力，并返回 `OWN_TASKS`。
3. 其他账号逐项检查本查询原读取能力。只有执行能力、没有全局读取能力的 Q06/Q07 账号，也只能使用 `OWN_TASKS`。
4. `AccessScope` 只由策略私有构造，不由客户端创建；读取器必须在 SQL 的计数、分页、聚合和关联之前应用 tenantId 及必要的 assignedDriverId。不能查询全量后仅隐藏明细。
5. `requireSource(sourceTenantId, assignedDriverId)` 补充核对实际行租户及本人归属，同时检查当前身份仍与授权时一致。它不能替代 SQL 范围条件。Scope 仅用于本次调用，不放入跨请求缓存；每次请求重新计算权限，改派后重新读源。
6. 分仓查询先整体关闭，不能把 warehouseCode 当作标签叠在全局数上。后续必须同批交付精确仓库归属、聚合过滤、无位置处理及越权测试，才能逐查询放开。
7. 原部门/客户数据规则仍须保留；尚不存在的细粒度策略不宣称已经实现。如果原来源不能满足被要求的范围，新读取器先禁用对应组合。

核对种子：`rd_erp_clean.sql` 和 `rd_erp_upgrade_slim.sql` 中的 `rd_production/rd_warehouse/rd_sales/rd_audit/rd_readonly/rd_quality/rd_warehouse_operator/rd_forklift_driver`。不是新增八类账号，也不替部署环境自动补权限。公开演示 admin 与私有系统管理员仍按实际授权区分；不因为“领导/综合项目部”等名称直接放行。

## 7. 后续读取器接入门槛

- 只读服务必须先调用 policy，使用返回的服务器范围；源查询失败、归属不明和不完整计数不得返回 KNOWN。
- 对总计、重量、列表和来源使用一致过滤与一致读取快照；同页 join 成员时避免放大主对象计数。
- 为 Q03-Q05 增加明确状态、真实成员、空结果、跨租户、重复成员及重量未知的数据库用例，完成 S1-02 后再增加查询入口。
- 为 Q06/Q07 增加两司机交叉访问、改派、任务状态和精确详情深链用例；为 Q01/Q02/Q08 增加反向流水、跨日、旧台账和正常 claim 用例。
- 查询行中的跳转只提供受控 sourceType/sourceId/actionCode，前端映射既有路由；不返回任意 URL，不产生确认/出入库写入。
- Q09/Q10 只有在提醒投影、原来源复核、授权后计数和扫描健康完成后才可开放；不得只移除 reserved 判断。
