## Transformation

Python 3.13.0 and fontTools 4.63.0 were used. The supplied bundled Python did not
have fontTools; the existing Python 3.13 installation did. Nothing was
installed or changed in the Python environment or project dependency files.

The upstream sole axis spans 100-900 with default 100. The script instantiates
`wght=400`, removes the resulting variable tables, preserves every glyph and
mapped codepoint, and renames the internal family/subfamily/full/PostScript/
unique/version/WWS names. Copyright, trademark, manufacturer, designer, source
URL, license text and license URL name records are preserved. The upstream
reserved name `Source` is not used as the derivative's primary name. This follows
the [OFL modification guidance](https://openfontlicense.org/ofl-faq/).

The upstream `head.modified` timestamp is retained for stable builds. There is no
claim of endorsement by Google, Adobe or the Noto project. License: OFL-1.1.

Run from the checkout root. Every shell command uses RTK:

```powershell
rtk proxy python -B scripts/verification/assist-fonts/rebuild-font.py
rtk proxy node scripts/verification/assist-fonts/test-pdfme.mjs
rtk proxy python -B scripts/verification/assist-fonts/verify-pdf.py
```

The rebuild requires network access to official GitHub APIs and fontTools 4.63.0.
The PDF test is offline and uses the already-installed project dependencies; no
install, service, browser, database, or production label UI is involved.

Verified on 2026-10-15:

## Embedded Subset Caveat

fontkit's PDF-only subset uses the valid legacy TrueType `true` signature and
writes zero table checksums for `head`, `hhea`, `loca`, `maxp`, `glyf`, and `hmtx`.
It omits several standalone-font tables. It must not be extracted and sold or
presented as the delivered standalone TTF. The verifier records this explicitly,
allows only zero omitted checksums (not arbitrary checksum mismatches), and
checks successful PDF rendering/text extraction independently. This caveat does
not apply to the shipped complete asset, whose signature is `00010000` and whose
strict checksum/decompilation validation passed. No pdfme/fontkit code was changed.
