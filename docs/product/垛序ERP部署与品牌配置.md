# 垛序 ERP

生产与仓储协同系统，当前覆盖生产任务、批次与独立包件、质检、库位、库存、入库、装车出库和追溯。平台品牌与使用企业的名称、客户资料及单据抬头分开。

## 包码诊断与AI整理

有包件查询权限的账号，在内部包码详情的“包码问答”查看核对清单：同一产出记录的ERP规则检查，含影响包数、责任岗位、字段依据和样例，不代表全仓可发量，不代替质检/仓管过账。

现场问句在本机匹配到状态、进度、下一步、风险核对或交接摘要，不外发原文，不自动请求；未知、写库指令、多意图和指定吨数配货回到受控选择/原任务。登记重量不是实磅或可发量。

GLM默认关闭，清单/本地识别仍可用。“请求整理”需负责人核定服务器模型、费用和额度，外发仅原批准流程状态、汇总及受控解释键；单包重量和客户/包码/库位/人员/原文/附件不直接送模型。未知结果保留原请求，核对原回执，不自动付费重试。实机和真模型另验收。

## 品牌配置

默认名称“垛序 ERP”，简称“垛序”。前端公开配置仅包含产品名称和本地图片文件名，不能写入密钥或业务数据。

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| VITE_APP_TITLE | 垛序 ERP | 浏览器、登录和主框架名称 |
| VITE_PRODUCT_SHORT_NAME | 垛序 | PDA、看板及纸质标签产品名称 |
| VITE_PRODUCT_SUBTITLE | 生产与仓储协同系统 | 登录、框架及产品元信息 |
| VITE_PRODUCT_LOGO | duoxu-mark.png | public目录下的本地PNG/WebP/JPG图片；不支持外站或脚本地址 |

前端默认值在frontend/.env，按部署环境覆盖后重新执行pnpm build:prod。真实企业名、客户、产品、单据、重量和库存仍来自ERP业务资料，不能把这些记录全部替换为平台名称。

## 二维码地址

新环境必须核定RD_DIGITAL_LINK_BASE_URL，例如企业实际可达服务器的HTTPS地址加/pkg。默认http://localhost:9000/pkg只用于本机开发，不代表手机或公网可以访问，也不是已经注册的品牌域名。Compose将此变量显式传给后端。

已生成包件优先使用数据库保存的qr_code，改变平台品牌或新包域名不重写旧包号和旧码地址。旧码仍能被内网解析为原包号；原域名是否仍可从外部打开，需要保持其服务/兼容入口并单独验收。没有已存URL的历史包只能回退当前配置，需要现场核对，不能虚构原标签。

## 二维码资源与公开护照

同一包码仍是原稳定身份和原追溯入口，状态变化不重新编号或重新贴标签。详情页新增“二维码资源与公开护照”：可复制原标签身份链接，打开资源目录/机器文档，下载公开快照。资源由本部署自有服务器提供，不需要 GS1 公共解析服务；不是 GS1 认证标识、法规数字产品护照或电子签名。

| 形式 | 同包码入口 | 返回内容 |
| --- | --- | --- |
| 网页 | `/pkg/{包码}`，或 `resource=web` | 原公开/内部权限追溯与岗位入口 |
| 公开快照 | `resource=passport`，或 `Accept: application/json` | 固定版本、原身份、公开内容和 SHA-256 摘要 |
| 机器文档 | `resource=document`，或 `Accept: application/ld+json` | 内嵌自有词汇的公开 JSON-LD；不抓取外站上下文 |
| 资源目录 | `resource=links`，或 `Accept: application/linkset+json` | 原身份 anchor 与当前自有服务器的资源 href |

快照只含现有公开产品/炉号炉层/登记重量/日期、受控状态和精简里程碑，不含客户、库位、单据、人员、内部 ID、测值、附件或自由备注；内部页下载也强制读取公开服务。待检或未审核的质检结论保持未知，不包装为合格。登记重量不是装车实磅；事件时间使用 ERP 本地时间语义。

选择下载的 JSON 文件后，本机核对版本、包码、公开字段和实际 UTF-8 内容摘要；文件不上传，不执行文件地址。再点“核对服务器当前记录”才请求本部署当前公开数据。摘要一致不是可信来源签名或实物防伪；文件与服务器不同也可能是记录更新，不自动判断假货。断网、错误文件、摘要不符或缺少 WebCrypto 时明确显示未核实。本机回环地址可以验证；普通厂区 HTTP 地址可能没有安全上下文，实际部署须配置 HTTPS 并实机验证。

容器必须配置 `RD_PUBLIC_TENANT_ID` 为本部署组织，公开资源固定该组织并清除登录/访问组织上下文，不改内部权限。新地址配置段只支持 ASCII 字母、数字、下划线、连字符；公开链接查询只允许规范的 `resource`、`workMode`、`internal`，登录凭据不进入 URL。重复/非法格式拒绝，表示各自有独立 ETag；默认网页地址不重定向到陌生站点。

## 库位空间视图

仓管在“入库上架”的库位地图查看自建示意、已登记行列或清单。先选择仓库/区域/库位层级，可缩放、平移和适配视图；点击库位查看在库包数/登记吨数、预留量、可用容量和关联上架任务。预留不是实际入库；没有容量上限按“未设上限”显示，未知或异常数据不能当作零。

默认自建图只按 ERP 已有的有效库位身份排列，不新建真实库位，不表示厂区实测距离、通道、货物自动定位或 GPS，不将绘图坐标写回 ERP。已登记行列模式依据原行列层信息布置，缺失/冲突项进入待核清单，不猜位置。身份无效项不能选入派单。现场布局须由仓管核定后维护。

空闲、部分占用、已满、冻结/不可用和状态待核以颜色加文字区分。仓管有原创建权限且库位可用时，“设为计划库位”仅选择原派单表单，不能直接更新包件位置或过账。资料读取、派单和最终入库仍受原角色授权；账号、组织或权限变化会清除旧资料，迟到响应不能串到新库位。司机不因此增加扫码、选位或库存确认责任。

上架任务详情展开“任务库位示意”，高亮计划/最终库位；装车任务详情展开“整车任务库位示意”，按记录的库位代码精确、唯一匹配高亮整车任务位置，不拆装车小组。任务记录位置不是保证货物此刻的物理位置；未知/不唯一匹配须人工核对，不自动改位置。

地图复用本地 Leaflet 1.9.4（BSD-2-Clause），不加载外部地理底图、瓦片、CDN或自动导航服务。当前视图工具与框架常用图标使用本地资源；其他未逐项验收模块不能据此宣称全平台离线。发布时保留 `frontend/licenses/leaflet-LICENSE.txt` 和 `frontend/licenses/lucide-LICENSE.txt`，后者包含 ISC 与所衍生 Feather 图标的 MIT 声明。库位状态仍由本部署 ERP 数据提供，互联网断开不等于 ERP 服务器失联。

空间维度可切换“平面/立体”，默认保留原平面，立体按需加载本地Three.js0.186.1。立体显示库位底板、吨袋占用图示、库位号和原包数/登记吨数；旋转、缩放、俯视或复位只改变观察视角。点击库位仍打开同一资料侧栏，上架/整车任务仍按原身份高亮，不拆任务或改变确认职责。

每个占用库位的一个吨袋是状态图示，不等于该位只有一包，也不表达实际包件坐标、货物堆高、炉层或仓库实测结构。未知包数不画成确定有货，预留不计入在库；实际明细和位置以ERP及仓管核定为准。支持WebGL2的浏览器才能显示立体，不支持、初始化失败或上下文丢失时明确提示并返回平面；原清单仍可使用。离页/切换/注销会清理画布与绘图资源。部署时另保留 `frontend/licenses/three-LICENSE.txt` 原MIT通知，实体PDA性能、真触摸设备和厂区网络另行验收。

立体图新增明亮仓库外形、地坪和边界标线，均为本地示意几何，不代表实际建筑或通道；默认仍是平面。状态筛选保持位置不重排，并显示当前仓库/区域/层级的真实包数、登记吨数和预留库位；没有行列的位置仍在范围统计和待核清单中，已登记模式不给它们编造坐标。

仓管可按库位号查找，或在有原包件与库存查询权限时输入/扫码读取包码、二维码内容并定位登记库位。只请求本部署，不访问标签中其他主机；包件与库存位置、版本或当前在库状态不一致时拒绝定位旧位置。查货不等同入出库核验，不能自动更新库存；不是实物实时定位。切换筛选/范围、身份变化或数据刷新会取消失效查询。部署保留 `frontend/licenses/smart-warehouse-LICENSE.txt` 原MIT通知；只参考其白昼场景，不引入模拟设备或外部GLB。

## 仓储空间总览

有原库位查看权限且不属于叉车司机岗位时，ERP工作台首屏展示“仓储空间总览”，并提供独立菜单与 `/warehouse-space` 页面。默认立体，可切换全部仓库、指定仓库、库区或库位层级。首屏保留紧凑工具栏，筛选图标展开状态筛选、包码/二维码查询和库位查找；支持全屏、旋转、俯视、适配。手机端库区导航为单行滚动，原入库与出库页面仍保留原操作及默认平面。

总览只读：使用原ERP登记数据，不新增库存、位置写入或派单确认。库存/任务详情通过精确库位ID读取，未知量保留待核，重复/无效身份不计入；没有通道或位置实测数据时，分区排布均为自建示意。吨袋图示不是实物袋数或堆高。全仓的范围是当前可见登记仓库，不承诺物理现场自动定位。

每五秒在可见页面同步登记数据，显示更新时间；同一快照保留场景和视角，但重取所选库位明细。库位身份消失或不再匹配则关闭资料，账号、组织、权限或岗位改变后清除旧数据，离页不接受迟到响应。更新失败显示警告，不能以旧画面替代仓管现场确认。司机不增加总览、扫码或确认权限；直接打开无权页面进入403，匿名访问先登录。

使用现有本地Three/Leaflet/Lucide和原许可，无新依赖、库表或GS1账号；当前总览相关角色导航已验证不访问图标外站，不由此宣称全系统所有模块均完全离线。当前运行的是本地开发预览，不是安装新试运行包或现场验收。

## 部署边界

沿用Spring Boot、Vue、MySQL与Redis，当前固定单组织运行，不宣称已经具备多组织SaaS。新客户应使用独立数据库和账号，不复制其他客户生产数据；初始化脚本中的业务示例映射需在交付前按客户核定。组织名可在企业资料中维护，升级不以平台品牌覆盖组织名。

GLM辅助接口默认关闭。启用前确认具体模型、预算、数据范围和私密环境配置；本期只允许流程状态与登记汇总，AI不修改库存或替代人工确认。实体设备、网络、实际单据和岗位签字须各自验收。
