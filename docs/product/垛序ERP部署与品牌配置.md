# 垛序 ERP

生产与仓储协同系统，当前覆盖生产任务、批次与独立包件、质检、库位、库存、入库、装车出库和追溯。平台品牌与使用企业的名称、客户资料及单据抬头分开。

## 包码诊断与AI整理

有包件查询权限的账号，在内部包码详情的“包码问答”查看核对清单：同一产出记录的ERP规则检查，含影响包数、责任岗位、字段依据和样例，不代表全仓可发量，不代替质检/仓管过账。

现场问句在本机匹配到状态、进度、下一步、风险核对或交接摘要，不外发原文，不自动请求；未知、写库指令、多意图和指定吨数配货回到受控选择/原任务。登记重量不是实磅或可发量。

GLM默认关闭，清单/本地识别仍可用。“请求整理”需负责人核定服务器模型、费用和额度，外发仅原批准流程状态、汇总及受控解释键；单包重量和客户/包码/库位/人员/原文/附件不直接送模型。未知结果保留原请求，核对原回执，不自动付费重试。实机和真模型另验收。

## 品牌配置

默认名称“垛序 ERP”，简称“垛序”。前端公开配置仅包含产品名称和本地图片文件名，不能写入密钥或业务数据。

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| VITE_APP_TITLE | 垛序 ERP | 浏览器、登录和主框架名称 |
| VITE_PRODUCT_SHORT_NAME | 垛序 | PDA、看板及纸质标签产品名称 |
| VITE_PRODUCT_SUBTITLE | 生产与仓储协同系统 | 登录、框架及产品元信息 |
| VITE_PRODUCT_LOGO | duoxu-mark.png | public目录下的本地PNG/WebP/JPG图片；不支持外站或脚本地址 |

前端默认值在frontend/.env，按部署环境覆盖后重新执行pnpm build:prod。真实企业名、客户、产品、单据、重量和库存仍来自ERP业务资料，不能把这些记录全部替换为平台名称。

## 二维码地址

新环境必须核定RD_DIGITAL_LINK_BASE_URL，例如企业实际可达服务器的HTTPS地址加/pkg。默认http://localhost:9000/pkg只用于本机开发，不代表手机或公网可以访问，也不是已经注册的品牌域名。Compose将此变量显式传给后端。

已生成包件优先使用数据库保存的qr_code，改变平台品牌或新包域名不重写旧包号和旧码地址。旧码仍能被内网解析为原包号；原域名是否仍可从外部打开，需要保持其服务/兼容入口并单独验收。没有已存URL的历史包只能回退当前配置，需要现场核对，不能虚构原标签。

## 二维码资源与公开护照

同一包码仍是原稳定身份和原追溯入口，状态变化不重新编号或重新贴标签。详情页新增“二维码资源与公开护照”：可复制原标签身份链接，打开资源目录/机器文档，下载公开快照。资源由本部署自有服务器提供，不需要 GS1 公共解析服务；不是 GS1 认证标识、法规数字产品护照或电子签名。

| 形式 | 同包码入口 | 返回内容 |
| --- | --- | --- |
| 网页 | `/pkg/{包码}`，或 `resource=web` | 原公开/内部权限追溯与岗位入口 |
| 公开快照 | `resource=passport`，或 `Accept: application/json` | 固定版本、原身份、公开内容和 SHA-256 摘要 |
| 机器文档 | `resource=document`，或 `Accept: application/ld+json` | 内嵌自有词汇的公开 JSON-LD；不抓取外站上下文 |
| 资源目录 | `resource=links`，或 `Accept: application/linkset+json` | 原身份 anchor 与当前自有服务器的资源 href |

快照只含现有公开产品/炉号炉层/登记重量/日期、受控状态和精简里程碑，不含客户、库位、单据、人员、内部 ID、测值、附件或自由备注；内部页下载也强制读取公开服务。待检或未审核的质检结论保持未知，不包装为合格。登记重量不是装车实磅；事件时间使用 ERP 本地时间语义。

选择下载的 JSON 文件后，本机核对版本、包码、公开字段和实际 UTF-8 内容摘要；文件不上传，不执行文件地址。再点“核对服务器当前记录”才请求本部署当前公开数据。摘要一致不是可信来源签名或实物防伪；文件与服务器不同也可能是记录更新，不自动判断假货。断网、错误文件、摘要不符或缺少 WebCrypto 时明确显示未核实。本机回环地址可以验证；普通厂区 HTTP 地址可能没有安全上下文，实际部署须配置 HTTPS 并实机验证。

容器必须配置 `RD_PUBLIC_TENANT_ID` 为本部署组织，公开资源固定该组织并清除登录/访问组织上下文，不改内部权限。新地址配置段只支持 ASCII 字母、数字、下划线、连字符；公开链接查询只允许规范的 `resource`、`workMode`、`internal`，登录凭据不进入 URL。重复/非法格式拒绝，表示各自有独立 ETag；默认网页地址不重定向到陌生站点。

## 部署边界

沿用Spring Boot、Vue、MySQL与Redis，当前固定单组织运行，不宣称已经具备多组织SaaS。新客户应使用独立数据库和账号，不复制其他客户生产数据；初始化脚本中的业务示例映射需在交付前按客户核定。组织名可在企业资料中维护，升级不以平台品牌覆盖组织名。

GLM辅助接口默认关闭。启用前确认具体模型、预算、数据范围和私密环境配置；本期只允许流程状态与登记汇总，AI不修改库存或替代人工确认。实体设备、网络、实际单据和岗位签字须各自验收。

产品名称、标识和本地功能不等于商标注册、域名归属或正式商用验收。保留复用框架和依赖的许可证、版权及必要声明。
