# 第 10 周性能与并发验收记录

> 验收日期：2026-07-10  
> 范围：索引优化、5,000/20,000 行 Excel 解析、并发订单匹配、并发出库、重复确认

## 1. 数据隔离

- SQL 压测仅使用独立数据库 `rd_erp_perf`，不向试运行数据库写入合成大表数据。
- API 并发测试仅连接 `127.0.0.1:48080`，业务编号统一使用 `PERF-*` 前缀。
- API 测试在 `finally` 中删除日报汇总、库存流水、出库单、匹配记录、订单和库存批次。
- 测试结束后复核日报、库存、订单、匹配、出库六类核心表，残留测试记录均为 0。

## 3. MySQL 查询计划

`rd_erp_perf` 为库存、流水、订单、日报和 Excel 暂存表分别生成 20,000 行数据，并执行 `ANALYZE TABLE` 和 `EXPLAIN ANALYZE`。

| 查询 | 优化前 | 优化后 | 结论 |
| --- | ---: | ---: | --- |
| 库存台账状态分页 | 42.5 ms | 0.37 ms | 使用租户、状态、日期组合索引，消除全量排序 |
| 同客户型号匹配候选 | 0.97 ms | 1.13 ms | 稳定低于 3 ms，返回 200 个候选后排序 |
| 未结订单日期分页 | 46.1 ms | 0.19 ms | 使用租户、软删除、日期顺序索引 |
| 日报区间趋势 | 39.4 ms | 21.7 ms | 使用日报区间索引，仅扫描日期范围 |
| 看板库存聚合 | 22.2 ms | 25.2 ms | 使用覆盖索引，避免优化器误选后升至约 54 ms |
| 库存流水日期分页 | 0.36 ms | 0.29 ms | 保持低延迟并补齐租户前缀 |
| 读取 20,000 条有效导入行 | 41.2 ms | 40.3 ms | 已是顺序读取，耗时主要来自返回全部数据 |

索引升级脚本：`backend/sql/mysql/rd_inventory_week10_indexes.sql`。脚本会检查索引字段顺序后再重建，可重复执行。

当前剩余风险：看板库存指标仍是全量聚合。20,000 行满足当前验收线，但百万级库存批次应增加按租户维护的指标快照或 Redis 短时缓存，避免每次打开看板扫描全部有效库存。

## 4. 并发业务验证

脚本：`scripts/performance/Test-RdOutboundConcurrency.ps1`

### 4.1 并发订单匹配

两个订单各申请 80，同时匹配同一批 100 库存：

- 返回码：`0`、`1080310003`
- 最终库房数量：100
- 最终锁定数量：80
- 最终可用数量：20
- 结论：只有一个匹配成功，不会超额锁库。

### 4.2 并发出库

同一库存批次已分别锁定给两个订单，各 50，同时确认两张出库单：

- 返回码：`0`、`0`
- 最终库房数量：0
- 最终锁定数量：0
- 累计出库数量：100
- 结论：两张单串行获得库存行锁，最终数量准确且不为负数。

### 4.3 重复确认

两个请求同时确认同一张数量为 10 的出库单：

- 返回码：`0`、`1080500002`
- 最终库房数量：0
- 累计出库数量：10
- 结论：仅第一次确认成功，第二次在获得行锁后识别到状态已变化，没有重复扣减。
