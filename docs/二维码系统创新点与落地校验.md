# 二维码系统创新点与落地校验

## 一、创新点定位

本项目二维码不是单纯贴一个查询码，而是围绕碳化硅吨袋现场作业形成“一包一码、批次代表扫码、岗位权限联动、追溯可查”的数字化管理入口。二维码保留每包独立身份，同时在入库、出库等高频现场动作中减少逐包找单和重复录入。

## 二、核心创新点

| 创新点 | 设计内容 | 现场价值 |
| --- | --- | --- |
| 自建数字链接 | 采用 `https://id.tjldsic.com/pkg/{packageCode}`，由企业自有服务器解析和展示 | 不依赖国际平台，数据口径和展示字段可由企业自己控制 |
| 一包一码不变 | 每个吨袋仍有唯一包号、二维码、重量、生产、质检、库位和出库记录 | 出问题时可以追到具体一包，不把批次统计做成粗账 |
| 批次代表扫码 | 仓管扫描同一装车任务中的任意一包，系统带出整车任务和包件清单 | 不需要逐包先找单，现场确认更快 |
| 批量确认可拆分 | 默认选中未确认包件，仓管可剔除未实际装车包后再确认 | 适应现场少装、漏装、换包、库位临时变化 |
| 复核后直接过账 | 装车任务全部复核后，仓管一键确认出库，系统自动生成正式出库单并过账 | 扫码不只做记录，还能形成库存扣减、包件已出库和库位释放 |
| 同码不同入口 | 同一个二维码，公开客户看到追溯信息，内部人员按权限进入质检、入库、出库、库存等动作 | 避免各部门找不同菜单，减少录入路径 |
| 按真实任务定位 | 查询当前有效任务，并由服务器按查询权或司机本人归属返回引用；在库包已派装车时优先进入既有任务 | 不依赖包件状态猜任务，减少重新找单及重复派货 |
| 司机减负 | 叉车司机只看任务和货位资料，按派单搬运；扫码确认和库位更新由仓管负责 | 符合现场责任边界，不把库位账交给司机维护 |
| 可变数据不上码 | 二维码只存稳定地址和包号，库位、状态、质检、出库等动态信息从服务器实时读取 | 货位变化快时无需重打二维码 |
| 重复提交幂等 | 扫码确认使用幂等键，网络重试不重复计数 | 适应车间网络波动和 PDA 重复提交 |
| 原请求结果可核定 | 仓管可查询同一原请求是否已执行、是否已明确过期未执行或仍未知；只确定结果后结束本机待核 | 避免断网后盲目再扫码或把成功请求当作未执行 |
| 批次抽检精确归属 | 同来源实际覆盖包与实际样包独立登记；可检整批一键选择，结论只写覆盖成员 | 减少逐包重复登记，同时能分清“被抽样”和“由本次抽检覆盖” |
| 事务领域审计 | 状态、成员、活动占用与必要质检事件同事务提交，失败全回滚 | 不会出现半批放行或有结论却没有可查操作记录 |
| 受控扫码问货 | 已有包件查询权限的内部账号，可按当前状态、来源登记进度、下一步三种问法，请GLM整理已核实的ERP要点；只外发受控状态与同源汇总，不外发身份、单包重量或附件 | 在真实事实旁减少理解与找流程的负担；AI不编造数量，不代替人工确认；本轮本地准备完成，真实模型/费用确认后才启用 |
| AI原请求保护 | 纯查询回执、Redis预留nonce与指纹、次数限额、同浏览器持久待核和Web Locks、身份/租户单调失效 | 关页重开或结果失联时可保留原请求，不因核对回执而重复计费；跨设备和平台硬预算仍属真实接入门槛 |

## 四、落地校验要求

1. 线上码必须用正式域名实扫通过，不能只凭本地页面判断可用。
2. 至少选择一张真实提货单和一车真实装车任务进行测试。
3. 仓管扫描任意一包后，应能带出同任务全部待装包件。
4. 仓管批量确认后，每包明细仍能查看独立包号、重量、炉号、炉层、库位和确认时间。
5. 仓管确认出库过账后，应能形成正式出库单、库存流水、包件已出库状态和库位释放记录。
6. 已确认包再次被选中时，系统必须防止重复计数。
7. 叉车司机页面只显示任务和搬运资料，不出现库位更新、扫码确认、最终出库按钮。
8. 标签正式批量打印前，必须完成 PDA/手机在现场光照、粉尘和网络环境下连续扫码验收。

## 五、2026-10-11 标签创新点验证

标签同时呈现稳定二维码、独立包号、客户、型号、炉号炉层、重量和生产日期，现场可直接粗看；动态库位不印入标签，避免挪位后反复更换标签。现有生产记录可整批展开并打印，已贴标包件可带原因补打。首次确认在同一事务内逐包登记，先校验全组再写入；补打只追加日志，不改变在库状态、原包号或库位。

本地已核对 10 张标签并独立解码原图和打印 PDF 渲染图；Web 实测和数据库核对首次 10 条、补打 1 条，重复首次确认及缺少原因均被拒绝。详细记录见 `docs/acceptance/E3标签打印与补打本地验收记录.md`。上述为软件和模拟操作证据，实体打印与现场连续扫码尚未验收。

## 六、2026-10-11 统一入口联调

查询同一个在库包码后，仓管可以打开已关联的装车任务，司机只得到本人任务，商务可以查看有权限的提货单；生产和质检可进入各自有权限的标签、生产记录或检验单。任务、源单和最新质检记录按精确 ID 定位；同批包件可直接点击切换。快速切换时，过期响应不覆盖新的包件信息。

本地已用七账号实际登录验证内外视图、动作差异、本人任务边界与目标页跳转，并核对库存、库位、任务进度、库存流水及扫码记录在查询前后不变。默认角色目录授权遗漏已在基线与升级脚本中修复。记录见 `docs/acceptance/E4统一扫码入口角色联调本地验收记录.md`；上架侧旧扫码职责、岗位 PDA 和完整事件链仍列为后续，不作完成声明。

## 七、2026-10-11 入库代表码与职责后续

入库侧已补仓管代表码识别任务、勾选实际到位包和批量核验。司机上架 PDA 去除扫码、确认入库与库位操作，只读本人任务并反馈异常。批次核验保留每包独立记录，不将未到位包一起登记；同请求重试不重复计数，旧版本不能覆盖新的派单。最终位置由仓管确认后统一入库，动态位置从服务器查询，仍不写入纸码。

三包模拟场景实际 Web/数据库验证通过：先核验一包、重试不加计数，再核验两包，最后形成三条入库流水；双请求并发只有一笔成功；按新职责复跑 B6 权限、审计和单包并发均通过。记录见 `docs/acceptance/E4仓管批次入库与司机免扫码本地验收记录.md`。本节更新此前“上架旧扫码职责待整改”的状态，岗位 PDA 全状态、E5 完整事件链和实体设备仍未关闭。

## 九、独立生产任务与低负担登记

班长建立客户、业务日期、班次任务，PDA 选择后自动带出；实际型号、炉号炉层和净重按产出记录填写，一条记录可生成多个独立包码。同任务不同规格/炉层/重量仍各有源记录，不把任务当成统一质量结论或仓储过账范围。工人按预填标签装包贴标，不增加生产端逐包扫码职责。

真实请求编号绑定内容和录入身份，网络丢响应后只重试原请求；修改草稿和任务头不能释放原创建编号，旧任务/旧码保持不变。打印按任务读取实际各包资料，服务器拒绝跨任务混入，补打保留原身份。

本地任务 6 的两条产出生成 10 包/8400 kg，实际 PDA 录入、确认和生成、任务打印、跨任务拒绝及补打验证通过；10 页 PDF 二维码独立解码通过。记录见 `docs/acceptance/E3生产任务标签与生产PDA本地验收记录.md`。炉号/层候选、全岗位入口和实体扫码继续，不以源模型上线代替工厂验收。

## 十、岗位工作台与原值候选

新 `/pda` 只按岗位和已授能力显示真实入口，不把后台菜单缩小。生产选实际任务并可选已有完整炉号/层值；司机只看本人未完成的上架/装车任务、目标与进度，不显示扫码控件；管理/只读默认查询。QR 从工作台解析到同一身份，能带原任务参数返回独立现场页，不改变稳定纸码。

七账号、21 个身份/宽度组合、登录往返与真实候选选择已验证；查询不会改变已填炉号层值、包身份或库存。缺失/停用字典不编造标准，历史标记不重写。详见 E4 岗位工作台本地验收记录；当前质量/仓管 Web 深链不能代替 D3 真批次抽检和 D4 移动核验，完整 E 原目标继续保留。

## 十一、2026-10-11 批次抽检与质检岗位入口

新增独立质检 PDA `/pda/quality`。扫码仅定位，默认只选可检扫码包；“选择可检整批”读取同一真实生产产出的全部分页并选择实际可检包，用户可剔除本次不覆盖货物。实际抽样成员单独选择，不把生产任务内不同型号/炉层混为一个合格结论，不虚构抽检比例。

扫码包已通过时仍能定位同来源余包。每包仍有原包号、重量和生产来源；所选包共享实际检验单，但各包保留真实成员关系和“抽样/覆盖”标志，未选包不继承。内部同码能精确打开本包检验单，公开字段仍脱敏。

## 十二、仓管批量核验后的结果核定

同一吨袋二维码仍表示原包身份，不因任务调整或网络中断重新编号。仓管用代表码定位任务后，选择本次实际到位/装车成员；逐包身份、重量、核验和最终过账记录继续独立保存。核验不自动入库/出库，最终确认仍单独由仓管办理，司机只接任务、搬运和反馈异常。

网络结果未知时保留原账号、有效租户、任务、原版本、幂等键和成员。本机可“重试原核验”或“核定原请求”：服务器有匹配真实记录则恢复当前任务；只有无记录且服务器版本严格高于原版本，才经明确确认结束旧版待核并重新选实际包件；同版本或未来版本无记录均保留未知。任务和请求记录采用当前锁定读，不能用旧快照断言未执行。较新待核冲突不被旧页覆盖，跨标签换账号也不能执行旧确认。

## 十三、2026-10-12 一张装车任务的批量换货与逐包追溯

按用户“先写大头的”优先补C5主业务，D5后续细节暂缓。仓管Web/PDA在同一张装车任务内核定多对原包/替换包，精确查询真实在库货物，先检查整份计划的批准包数/重量、聚合履约和库存容量，再同事务切换占用与逐包历史。扫码核验和正式出库仍是两个动作，司机只看更新的整任务并搬运，不拆装车小组、不改库位或扣库存。

旧包不重新编号，仍在原库位；新包保持自己的二维码和实际源记录，未替换包的已有核验进度保留。换货后使用任务内新代表码继续核验实际成员，不沿用已换出的包码；换出/换入互相关联，完整生产/质检/库存来源不被覆盖。

网络返回未知时保留待核并禁用重复变更；同版本争用只能有一个成功，读回实际成员后才核实结果。账号/租户/生命周期代次变化使旧确认不可继续，库存包号定位不受模糊搜索第一页截断。
